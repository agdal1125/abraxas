# T018-P3-f 길과 풀 다시 고치기

`docs/tasks/T018-P3-faceted-direction.md`와 `docs/tasks/T018-P3-d-ground.md`의 쓰기 범위 그대로다. 셸 읽기는 자유롭다. 커밋·push 금지. 이번에는 `content/world/village.json`도 쓴다. 건물과 소품 GLB는 쓰지 않는다.

## 감독이 게임 화면에서 불합격시킨 것

1. **길이 깨진 스테인드글라스 같다.** 면마다 명도 차이가 너무 커서 삼각형 조각이 그대로 보인다. 길 끝과 경계는 뾰족한 삼각형 조각으로 끊긴다. 고칠 점: 면 명도 차이를 지금의 약 4분의 1로 줄여 멀리서 한 색의 흙길로 읽히게 한다. 면 내부 삼각형이 길을 가로지르는 줄처럼 보이면 안 된다. 경계는 짧은 변들이 이어진 완만한 다각형으로, 뾰족한 돌출이 없어야 한다. 폭은 지금보다 들쑥날쑥하지 않게 하고 길 끝은 둥글게 마무리한다.
2. **풀이 칙칙한 올리브색이다.** 활기가 없다. 채도가 조금 있는 맑은 풀색으로 올린다. 인물과 나무보다는 채도와 명도 대비가 낮아야 하고, 나무의 짙은 초록과 구별되어야 한다. 민트색으로 되돌리지 않는다. 큰 풀 얼룩의 경계가 직선 띠처럼 보이지 않게 경계 대비를 낮춘다.
3. **길이 어딘가로 이어져야 한다.** 오르(`char-d`) 쪽 길은 대장간 앞에서 끊겨 보인다. 대장간과 도서관 입구 앞까지 이어지는지 확인하고, 끊긴 곳은 길 데이터를 고쳐 잇는다. 도달성 검사를 통과해야 한다.
4. **소품 정리.** 대장간 앞에 통나무와 통이 같은 모양으로 흩어져 있다. 작업터 쪽 군집 2~4개로 모으고 빈 땅의 것은 없앤다. 도서관 앞 `book-stack`도 등간격으로 흩어지지 않게 모은다. 소품 ID가 심부름·대화·조사 대상으로 참조되는지 먼저 검색하고, 참조되는 것은 지우지 않는다. 같은 소품·크기·방향이 한 화면에 3개를 넘지 않게 회전과 크기를 달리한다.

예산은 같다. `terrain.png`만으로 합격시키지 말고, 가능하면 빵집 앞 구간을 확대 렌더해 면 대비를 판정한다.

`node client/scripts/check-abraxas-assets.mjs`, `node scripts/check-village-reach.mjs`, `npm --prefix client test`를 실행한다. 한국어로 삼각형·바이트 전후, 옮기거나 지운 소품 ID, 검사 결과, 끝내지 못한 항목을 보고한다.
