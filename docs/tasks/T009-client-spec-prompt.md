# T009 클라이언트 명세 프롬프트 (사람 제공 원본, 2026-11-01)

사람이 Astra(Codex `gpt-6-astra`) 리뷰·구현용으로 제공한 프롬프트 원문. 현재 결정(ADR-0005 Three.js, 공략 캐릭터 A·B·C·D, `game-design-policy.md`)과 다른 부분이 있으며, 그 처리 방향은 `docs/reviews/2026-11-01-quality-review.md`에서 정리한다.

목표 화질 기준: 사람이 지정한 레퍼런스 스냅샷(모여봐요 동물의 숲 스크린샷). **화질·밀도·연출 수준의 기준일 뿐, 캐릭터·에셋·고유 디자인은 복제하지 않는다.**

---

# Role & Goal
너는 Phaser 4와 TypeScript(strict)에 능통한 시니어 웹 게임 클라이언트 개발자야.
모바일 웹 심리 테스트형 연애 어드벤처 **Abraxas(가제)** 의 클라이언트를 만든다. 기억을 잃은 주인공이 약 30분 동안 마을 사람 4명과 지내며, 선택으로 16유형 중 '진짜 나'를 되찾는 게임이다.

작업 전에 저장소의 `AGENTS.md`, `docs/gdd/README.md`, `docs/adr/0001-tech-stack.md`, `.agents/rules/`를 먼저 읽어. 이 프롬프트와 그 문서가 충돌하면 `.agents/rules/game-design-policy.md`가 우선이고, 그다음이 기획서야. 아래 명세를 지켜서 모듈화된 코드를 작성해 줘.

- 클라이언트: TypeScript strict + Phaser 4 + Vite (`client/`)
- 대사·선택지: ink (inkjs 런타임)
- 데이터: 성향 가중치·맵·에셋 목록은 코드가 아니라 `content/` 아래 JSON
- 테스트: Vitest(로직), Playwright(모바일 뷰포트 E2E)
- Phaser API는 추측하지 말고 설치된 Phaser 공식 스킬(`.agents/skills/`)에서 확인해.

# 1. Graphics & Visual Directives (그래픽 명세)

동글동글하고 귀여운 심리 테스트 감성을, 쿼터뷰 농장 마을 화면으로 구현한다. 모바일 웹 로딩 속도가 최우선이라 실시간 3D 대신 **2.5D 프리렌더** 방식을 쓴다.

1. **2.5D 프리렌더 구성 (핵심)**
   - 배경: 3D로 만든 쿼터뷰(3/4 탑다운) 장면을 이미지로 구운 것. 레이어는 `바닥(ground)` → `오브젝트·캐릭터(y 정렬)` → `전경 가림막(foreground occluder)` 순서.
   - 캐릭터·NPC: 스프라이트. 발 위치(y) 기준으로 깊이를 정렬해서 나무·건물 뒤로 자연스럽게 지나가게 해.
   - 전경 가림막: 건물 지붕·나무 윗부분처럼 캐릭터를 가리는 부분은 잘라낸 스프라이트로 두고, 각자 기준선(baseY)으로 깊이를 정해.
   - 실제 아트가 나오기 전까지는 **단색 도형 플레이스홀더**를 쓴다(바닥은 색 블록, 캐릭터는 둥근 캡슐, NPC마다 다른 색). 에셋은 목록 파일(`content/assets/manifest.json`)로만 참조해서, 파일만 바꾸면 실제 아트로 교체되게 해.

2. **화면과 카메라**
   - 세로 9:16 고정. 기준 해상도 720×1280. 더 긴 화면에서는 줌을 유지하고 세로 시야만 늘린다. 노치·홈 인디케이터 안전 영역 안에 UI를 둔다.
   - 카메라는 플레이어를 부드럽게 따라간다(Lerp 추적 + 작은 데드존). 월드 경계 밖은 보이지 않게 막아.
   - 광장은 화면보다 큰 맵이라 카메라가 따라가고, 장소 씬은 한 화면짜리라 카메라를 고정한다.

3. **아트 스타일**
   - SD(치비) 2~2.5등신, 큰 머리와 단순한 표정. 공략 캐릭터 4명은 성별 중립 디자인, 주인공은 외형 요소를 최소화한 단일 디자인(커스터마이징 없음).
   - 컬러: 파스텔 톤 바탕 + 자연색 포인트(풀밭 초록, 흙길 주황, 꽃 분홍).
   - NPC 반응은 머리 위 이모티콘 버블(하트·물음표·땀방울)로 보여준다.

4. **실시간 시계 연동 조명**
   - 기기의 현지 시각(`new Date()`)으로 화면 색감을 바꾼다. 2D라서 광원 계산 대신 **장면 전체 색조(tint)·밝기 조절 + 발광 레이어(창문·가로등)** 로 표현해.
   - 기준 키프레임(시각은 데이터로 빼서 조정 가능하게):

     | 구간 | 시각 | 연출 |
     | --- | --- | --- |
     | 새벽 | 05:00–07:00 | 연보라 → 복숭아빛 |
     | 낮 | 07:00–17:00 | 따뜻한 흰색(색조 거의 없음) |
     | 노을 | 17:00–19:30 | 주황 → 보라 |
     | 밤 | 19:30–05:00 | 푸른 달빛, 창문·가로등 발광 켜짐 |

   - 키프레임 사이는 보간해서 끊김 없이 바뀌게 하고, 1분마다 다시 계산해.
   - 조명 계산은 순수 함수로 분리해: `getLighting(date: Date): { tint, brightness, lampsOn }`.
   - 밤에도 캐릭터와 글자가 잘 보여야 한다. 밝기 하한을 두고, UI 레이어에는 색조를 적용하지 마.
   - 실내 장소 씬은 따뜻한 실내 조명으로 고정하고, 창문 색만 바깥 시간대를 따른다.
   - 테스트용으로 URL 파라미터 `?time=19:30`이 있으면 그 시각으로 고정해.

# 2. Core Game Systems (게임 시스템과 데이터 구조)

전체 시스템을 미리 적어 둔다. Step 1은 일부만 구현하지만, 나머지가 나중에 붙을 수 있게 구조를 잡아 줘.

1. **월드와 걷기 그리드 (화면과 논리 분리)**
   - 배경 이미지와 별개로, 이동 가능 여부를 담은 **2D 걷기 그리드**가 월드의 논리 상태다. 셀 1칸 = 40px(기본값, 맵 데이터로 조정).
   - 광장 월드 1080×1920(27×48셀), 장소 씬 720×1280(18×32셀). 기본값이며 맵 데이터로 바꿀 수 있게 해.
   - 맵 데이터(`content/maps/<id>.json`):
     ```ts
     interface MapData {
       id: string;                 // 'plaza' | 'bakery' | 'library' | 'smithy' | 'festival-hq'
       size: { cols: number; rows: number; cellSize: number };
       layers: { ground: string; occluders: { key: string; x: number; y: number; baseY: number }[] };
       blocked: [col: number, row: number][];     // 걸을 수 없는 셀
       spawn: { col: number; row: number; facing: Facing };
       doors: { id: string; cell: [number, number]; target: string; targetSpawn: string }[];
       npcs: { npcId: string; cell: [number, number]; talkCell: [number, number]; facing: Facing }[];
       lightingMode: 'outdoor' | 'indoor';
     }
     ```
   - 마을 구조는 **허브 앤 스포크**다. 광장(허브)을 걸어 다니다가 문에 닿으면 장소 씬으로 전환한다.

     | 장소 (가칭) | 맵 id | 공략 캐릭터 |
     | --- | --- | --- |
     | 축제 준비 본부 | `festival-hq` | 루미 (축제 준비위원) |
     | 빵집 | `bakery` | 모카 (빵집 주인) |
     | 도서관 | `library` | 에코 (도서관 사서) |
     | 대장간 | `smithy` | 오르 (대장장이) |

   - 장소 씬의 에셋은 들어갈 때 내려받는다(Lazy Loading). 첫 화면에는 광장에 필요한 것만 받는다.

2. **플레이어 이동 (탭 이동, 한 손 조작)**
   - 상태 머신: `IDLE`, `WALK`, `INTERACT`(대화 중, 입력 잠금), `TRANSITION`(씬 전환 중, 입력 잠금).
   - 땅을 탭하면 걷기 그리드 위에서 A* 경로를 찾아 걸어간다(8방향, 벽 모서리 끼임 금지). 경로 탐색은 외부 라이브러리 없이 직접 구현하고 테스트를 붙여.
   - 갈 수 없는 셀을 탭하면 가장 가까운 걸을 수 있는 셀로 간다. 걷는 중에 다시 탭하면 새 경로로 바꾼다.
   - 탭한 지점에 작은 표시(물결 효과)를 띄운다.
   - NPC나 문을 탭하면 그 대상의 상호작용 셀(`talkCell`, 문 셀)까지 걸어간 뒤 상호작용한다. NPC 앞에서는 NPC 쪽을 바라본다.
   - 이동 속도·방향(4방향 스프라이트 기준)은 설정값으로 둔다.

3. **대화와 선택지 (ink)**
   - 대사는 ink로 쓰고 inkjs로 실행한다. 대화창은 화면 하단, 선택지는 2~3개의 큰 버튼.
   - 글자가 한 글자씩 나오는 타자기 효과. 탭하면 남은 글자를 바로 보여주고, 한 번 더 탭하면 다음 줄로 넘어간다. 자동 넘김은 끌 수 있고, 글자 크기를 조절할 수 있다.
   - 측정 문항은 ink 태그로 `content/scoring/` 데이터의 문항 id를 가리킨다. 태그 형식은 `content/scoring/SCHEMA.md`를 따른다. 가중치는 ink에 직접 쓰지 않는다.
   - **선택 즉시 확정(Commit-before-Reveal)**: 선택하는 순간 로컬과 서버(지금은 목업 API)에 먼저 저장하고, 그다음에 반응을 보여준다. 되돌리기 버튼은 없고, 새로고침·뒤로 가기로 다시 고를 수 없다.

4. **성향 시스템 (클라이언트는 연출용 계산만)**
   - 축 5개 A~E, 축마다 성향치 $s_k \in [-100, +100]$, 시작값 0. 주축 4개(A~D)가 16유형을, 보조축 E가 수식어를 정한다.
   - 선택지마다 가중치 벡터 $\Delta$를 가진다(주 적재 축 1개 ±8~15, 보조 적재 축 최대 1개 ±3~5):
     $$s_k \leftarrow \mathrm{clamp}(s_k + \Delta_k,\ -100,\ +100)$$
   - 유형 판정: 주축마다 $s_k \ge 0$이면 앞 글자, 아니면 뒤 글자. $|s_k| < 10$인 축은 '기억의 문' 타이브레이커로 정한다.
   - 결과 화면 막대: $p_k = 50 + |s_k|/2\ (\%)$
   - 수식어: $s_E \ge 10$ '오늘을 사는', $s_E \le -10$ '내일을 그리는', 그 사이 '오늘과 내일 사이'.
   - 딜레마 선택지의 가치 태그(Schwartz 10가치) 누적 상위 3개를 '내가 지킨 가치'로 보여준다.
   - 최종 결과는 서버가 선택 로그로 다시 계산해 확정한다. 계산 로직은 같은 데이터를 읽는 순수 함수로 두고, 서버(Go)와 같은 결과가 나오는지 골든 테스트로 확인할 수 있게 해.

5. **공략 캐릭터 4명과 성향 변동**
   - 스타팅 성향치(A/B/C/D): 루미 +30/+30/+30/+30, 모카 +30/+30/−30/−30, 에코 −30/−30/+30/−30, 오르 −30/−30/−30/+30. 보조축 E 스타팅값은 아직 미정이라 데이터에서 읽게 해.
   - NPC 장면의 측정 문항에는 기대 답변(그 축에서 NPC의 현재 극과 같은 쪽)이 있다.
     $$s_{npc,k} \leftarrow \mathrm{clamp}(s_{npc,k} + m \cdot 20 \cdot \mathrm{pole}_k,\ -100,\ +100),\quad m = +1\ (\text{일치}),\ -1\ (\text{불일치})$$
   - 일치는 강화(공감하는 반응), 불일치는 흔들림(생각에 잠기는 반응). 어느 쪽도 좋고 나쁨이 드러나면 안 된다.
   - 호감도 0~100, 시작 20. 기대 일치 +12, 담당 심부름 완료 +8, 공동 이벤트 편들기 +10. 화면에는 하트 5칸(20점당 1칸)만 보여준다.
   - **측정 문항으로 오른 호감도는 에피소드가 끝날 때 한꺼번에 하트로 채운다.** 즉시 뜨는 하트 버블은 측정과 무관한 행동(심부름 완료, 편들기)에만 쓴다.
   - NPC 상태: `IDLE`(제자리 대기 애니메이션), `TALK`(플레이어 쪽을 보고 고정).

6. **진행 구조 (약 31분)**
   - 프롤로그(2분) → 캐릭터 에피소드 4개(각 4.5분, 순서는 플레이어가 광장에서 고름) + 사이사이 막간 3개(각 1분) → 공동 이벤트 '마을 축제 준비'(3분) → 기억의 문(타이브레이커 4문항, 2분) → 고백(1분) → 기억 회복·결과 공개(2분).
   - 기억 조각: 주요 선택 1개당 1개, 화면 상단에 n/12로 표시.
   - 이어하기: 장면 단위 자동 저장. 인앱 브라우저를 나갔다 와도 이어서 한다.

7. **결과와 공유 (후속 단계)**
   - 결과 카드 3장('나', '그 사람', '마을'), 궁합은 두 유형의 같은 글자 수(0~4)로 5단계 문구.
   - 공유 카드는 canvas로 생성(9:16). 초대권 발급·소모·인당 최대 8장 판정은 서버만 한다. 클라이언트는 잔량 표시만.

8. **라이트 퍼즐 (후속 단계)**
   - 1~2분, 실패 없음, 힌트 무제한. 퍼즐 성공 여부는 측정하지 않고 퍼즐 앞뒤의 선택만 측정한다.

# 3. Constraints (항상 지킬 것)

- 플레이어에게 보이는 글에 축 이름·코드(A~E, O/I 등), 성향치, 호감도 숫자, 'MBTI'라는 단어를 넣지 않는다.
- 첫 화면 5초 이내, 초기 다운로드 10MB 이하(가안). 빌드 후 크기를 보고해.
- 카카오톡·인스타그램 인앱 브라우저에서 동작해야 한다.
- 화면 글은 한국어, 코드 식별자와 주석은 영어. 파일명은 소문자 kebab-case.
- 새 외부 의존성을 추가하면 이유를 PR 설명에 적는다.
- 끝났다고 말하기 전에 `npm run typecheck && npm test`를 통과시킨다.

# 4. Implementation Steps (단계별 출력 지시)
한 번에 전부 만들기 어려우니 아래 순서로 진행해 줘. 각 단계는 PR 하나로 올린다.

- **Step 1 — 마을과 이동**: 광장 씬과 장소 씬 4개(플레이스홀더), 걷기 그리드와 A* 탭 이동, y 정렬과 전경 가림, 카메라 추적, 문을 통한 씬 전환(페이드)과 복귀, NPC 4명 배치와 상호작용 지점, 실시간 시계 연동 조명.
- **Step 2 — 대화와 계산**: ink 대화창·선택지, 선택 즉시 확정 저장(로컬 + 목업 API), 성향치·호감도·NPC 흔들림 계산과 Vitest, 이모티콘 버블.
- **Step 3 — 한 바퀴 돌기**: 프롤로그 → 광장 → 에피소드 1개 → 막간 → 결과 카드까지 이어지는 수직 슬라이스, 기억 조각 HUD, 이어하기.
- 이후(별도 작업): Go 서버 API, 초대권, 공유 카드와 OG 이미지, 퍼즐, 공동 이벤트·기억의 문·고백.

우선 **Step 1**부터 해 줘. 구현 전에 파일 구조와 계획을 먼저 보여주고, 확인받으면 실행 가능한 상태까지 구현해.

## Step 1 범위
- 포함: 위 Step 1 항목, 맵 데이터 JSON 5개(광장 + 장소 4곳), 에셋 목록 파일, 플레이스홀더 그래픽.
- 제외: 대화·선택지·ink, 성향 계산, HUD, 저장, 서버 호출, 사운드. NPC를 탭하면 그 앞까지 걸어가 NPC를 바라보고, `npc:interact` 이벤트(`{ npcId }`)만 발생시킨 뒤 말풍선 자리에 '…'를 잠깐 띄운다.

## Step 1 완료 기준
1. `npm run dev` 후 모바일 뷰포트(390×844)에서 광장이 뜨고, 땅을 탭하면 장애물을 돌아서 걸어간다.
2. 플레이어가 나무·건물 뒤로 지나가면 가려지고, 앞으로 지나가면 위에 보인다.
3. 문 4곳으로 각 장소 씬에 들어가고, 출구로 나오면 광장의 그 문 앞에 선다.
4. NPC를 탭하면 상호작용 셀까지 걸어가 서로 마주 본다.
5. `?time=06:00`, `12:00`, `18:00`, `22:00`에서 색감이 다르고, 밤에도 캐릭터가 잘 보인다.
6. Vitest: A* 경로 탐색(우회, 도달 불가 시 가장 가까운 셀, 모서리 끼임 금지), `getLighting` 키프레임과 보간, 맵 데이터 유효성(스폰·문·NPC 셀이 걸을 수 있는 셀인지).
7. Playwright: 모바일 뷰포트에서 탭 이동, 문 전환 스모크 테스트.
8. `vite build` 결과 크기와 첫 화면까지 걸린 시간을 보고.
