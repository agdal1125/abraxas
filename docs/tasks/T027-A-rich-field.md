# T027-A 다채로운 들판

담당 game-engineer, 검수 메인 세션. 브랜치 `art/rich-field`. 사람의 말(2026-11-12): "풀이 너무 띄엄띄엄 있는데, 배경을 좀 더 오픈월드 같이 다채롭게 만들어줄 수는 없나? 웹 브라우저 기반 게임이라는 점도 체크해서 최적화도 해주고". 이 작업은 첫 줄 몫이다. 최적화 전반, 주소창, 인트로 버튼은 다른 작업이다.

## 목표

740×360 화면에서 풀밭이 빈 단색 면으로 보이지 않고, 걸어 다니면 구역마다 식생이 달라 보인다. 풀을 다시 키우지 않는다(어제 결정, 인물이 걷는 곳은 발목 높이 유지).

## 한 일

1. **땅 얼룩.** 지형 셰이더에 풀색 부분만 밝고 어두운 얼룩, 저폴리식 각진 면, 가까운 구역의 색 기운을 얹었다(`nature-biome.ts`의 `paintGround`). 새 텍스처도 드로콜도 없다. 길, 물, 돌 색은 그대로 둔다.
2. **촘촘한 잔디.** 후보 점 밀도를 44에서 96/u²로 올리고 얇은 구역에서도 포기 대부분을 남겼다(전체 5만 9천 포기). 포기 색에 구역 색 기운과 마른 풀 정도를 넣었다.
3. **다양한 층**(`nature-flora.ts`, 인스턴싱 5층). 들꽃(흰색, 분홍, 연보라, 노랑 다섯 꽃잎), 클로버와 낙엽 무더기, 낮은 덤불, 작은 버섯, 키 큰 풀.
   - 키 큰 풀은 길에서 1.1 u 이상, 구역 중심과 주민 자리에서 1.7 u 이상 떨어진 곳 가운데 나무, 바위, 벽 곁, 호숫가, 섬 가장자리에만 난다. 높이 최대 0.4 u(인물 키의 3분의 2 미만).
   - 구역별 조합(`BIOMES`): 어귀는 흰 들꽃과 클로버, 광장은 짧은 잔디와 분홍 꽃, 빵집은 따뜻한 땅색에 노랑과 분홍 꽃, 도서관은 서늘한 그늘에 연보라 꽃과 낙엽과 버섯, 공방은 마른 풀색에 노랑 꽃과 낙엽, 호숫가는 짙은 땅에 갈대 같은 키 큰 풀, 문 가는 길은 푸른 기운과 연보라 꽃. 구역 사이는 거리에 따라 섞인다.
   - 다리 위에는 놓지 않는다.
4. **먼 배경**(`nature-backdrop.ts`). 이 섬은 하늘에 뜬 섬이라 가장자리 바깥은 하늘 그라데이션이다. 먼 땅 대신 작은 떠 있는 섬 열두 곳과 낮은 구름 스물네 덩이를 한 메시에 넣었다. 구름은 공용 바람 시계로 천천히 흔들리고 `prefers-reduced-motion`이면 멈춘다. 가장자리에서 9 u 안에 있을 때만 그린다.
5. 지형 샘플러에 길, 물, 가장자리까지의 거리 지도를 넣었다. 충돌 검사는 공간 해시(`Obstacles`)로 바꿔 배치 계산을 줄였다.
6. 층마다 같은 `ScatterLayer`(`nature-layer.ts`)를 쓴다. 화면 근처 항목만 인스턴스 버퍼에 쓰고 카메라가 0.3 u 움직일 때만 다시 쓴다(전에는 0.18 u).

## 지킨 것

- 배치와 움직임은 위치, 시간, 주인공과의 거리에만 반응한다. 선택, 성향, 호감도에 반응하지 않는다. 별, 체크, 숫자, 하트, 노란 공 모양 소품 없음. 노랑 꽃은 납작한 다섯 꽃잎이다. `content/scoring/items.json`에 나오는 물건 모양은 새로 만들지 않았다.
- 새 광원, 후처리, GLB, 텍스처, npm 의존성 없음. 풀과 꽃은 그림자를 드리우지 않는다. 걸을 수 있는 칸을 막는 소품 없음.
- 건드린 파일: `client/src/scenes/nature*.ts`, 새 테스트 `nature-flora.test.ts`, `village.ts`에 `Nature` 입력 두 줄(`actors`, `outer`, `bridges` 전달).

## 수치

조건: 헤드리스 Chrome, SwiftShader, 740×360, DPR 1, `mobile: true`(폰 밀도 0.7), 같은 지점에 `teleport` 뒤 1.5초, `renderer.info.render`. 후처리 포함(실제 프레임). 전 값은 main `c6f26b8`.

| 지점 | 드로콜 전 → 후 | 삼각형 전 → 후 |
| --- | --- | --- |
| 어귀(스폰) | 82 → 88 (+6) | 44,349 → 57,652 (+13.3k) |
| 광장 | 87 → 92 (+5) | 49,187 → 57,809 (+8.6k) |
| 빵집 | 82 → 87 (+5) | 56,990 → 65,851 (+8.9k) |
| 호숫가 | 69 → 74 (+5) | 34,677 → 41,980 (+7.3k) |

예산(드로콜 +6 이하, 삼각형 +25k 이하) 안이다. 드로콜 +5는 새 인스턴싱 다섯 층이고, 어귀의 +6은 가장자리가 가까워 배경 메시 하나가 더해진 값이다. 호숫가 화면의 층별 그려진 수(들꽃과 클로버 밀도를 올리기 전 측정): 풀 2,189, 들꽃 78, 클로버 280, 키 큰 풀 67, 덤불 8, 버섯 2. 표의 수치는 밀도를 올린 뒤 다시 잰 값이다.

원인: 삼각형은 풀 포기가 전보다 늘고, 들꽃 열 장, 클로버 여섯 장, 키 큰 풀 아홉 장으로 늘었고, 땅 얼룩은 셰이더라 삼각형이 없다. 드로콜은 층마다 하나다.

로딩: 개발 PC 헤드리스에서 `Nature.build`(샘플러 약 60 ms, 배치 약 250 ms). 포기 수가 약 두 배라 전보다 배치 시간이 늘었다. 폰 값은 미측정.

## 확인

- `client`: `npm run typecheck`, `npm test`(35 파일 192 테스트), `npm run build`, `npm run check:size`(dist 7.66 MB, cinematics 12.49 MB) 통과. 루트 `node scripts/check-village-reach.mjs` 통과(도달 대상 77곳).
- 캡처(`docs/reviews/T027-A/`): 여섯 지점 전후 740×360(`*-before-after-740.jpg`, 왼쪽 전, 오른쪽 후), 섬 가장자리 여덟 곳(`rim-backdrop-740.jpg`). 직접 열어 인물의 발이 보이고 풀밭이 비어 보이지 않는 것을 확인했다.

## 미확인, 한계

- 실제 폰 프레임, 발열, 메모리, 로딩 시간은 미측정. SwiftShader 값은 상대 비교용이다.
- 844×390 캡처는 만들지 않았다. 한국어 E2E(`npm run e2e:play`)는 지시대로 돌리지 않았다.
- 떠 있는 섬은 가장자리 화면에서도 일부만 걸린다(대부분 구름이 보인다). 섬이 화면 위쪽에 잘려 보이는 경우가 있다.
- 땅 얼룩은 지형 셰이더 한 곳에서만 계산하므로 구역 수(7)와 색은 `BIOMES`에 고정되어 있다. 구역이 늘면 `ZONE_COUNT`도 바꾼다.

## 사람이 정할 것

- 구름과 떠 있는 섬이 마음에 드는지, 아니면 가장자리를 비워 둘지.
