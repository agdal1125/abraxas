## 세션 3 (windows) · 스테이징 배포 설정
- 유형: 인프라
- 시스템: 서버, 배포

### 한 일
- 진단 결과 출시를 막는 첫 조건이 배포라고 보고, 사람 승인을 받아 스테이징 배포 설정을 만들었다.
- Hosting의 `/v1` 연결, CSP와 보안 헤더, 해시 파일 캐시, Cloud Build 업로드 제한, 배포 스크립트를 넣었다.
- 서버에 uid당 분당 300회 제한을 넣었다. 넘으면 429이고 클라이언트는 기존 다시 연결 화면을 보여 준다.

### 확인
- 제한을 켠 상태로 한국어 E2E가 결과까지 통과했다. 비정상 응답은 없었다.
- 실제 CSP를 붙인 로컬 서버로 제목 화면, 마을, 글꼴, 영상 메타데이터를 확인했다. 처음 작성한 CSP는 Draco 워커를 막아 게임이 로딩에서 멈췄고, 고친 뒤 통과했다.
- 실제 Firebase 프로젝트가 없어 인증, App Check, Firestore, 배포 스크립트 실행, Hosting 실제 헤더는 확인하지 못했다.

### 다음
- 사람 준비가 끝나면 배포하고 docs/design/staging-deploy.md의 확인 항목을 돈다.
