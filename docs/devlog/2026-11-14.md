## 세션 3 (windows) · PC 창에서 걸을 때 풀·바닥·그림자가 바뀌던 문제
- 유형: 버그
- 시스템: 아트

### 한 일
- 사람이 PC에서 "움직이면 풀숲이랑 바닥이 바뀐다"고 제보했다. 원인 두 가지를 실제 게임에서 측정해 확인했다.
- 원인 1: 주인공을 늘 약 70px로 그려서, 1920×1080 창은 폰(844×390)보다 약 6배 넓은 땅을 보여 준다. 산포 층은 화면 안 항목을 월드 x 순서로 상한(풀 5,600, 클로버 2,200)까지만 채웠다. 그래서 풀이 화면 왼쪽 위에만 있었고, 걸으면 경계가 화면 가운데를 오갔다. 9.5칸을 걷는 동안 화면 가운데 풀 3,903포기가 켜졌다 꺼졌다.
- 원인 2: `Village.resize`가 `updateCamera`로 새 화면 높이를 재기 전에 그림자 범위를 계산했다. 창을 키우면 그림자가 주인공 둘레의 작은 네모 안에만 생겼다. 화면 높이가 맞아도 16:9 화면의 왼쪽 위 약 2%는 그림자 밖이었다.
- `ScatterLayer.update`는 화면 안 항목을 순위 단계(256)별로 센다. 상한을 넘으면 순위가 높은 단계부터 빼고, 뺀 단계는 상한의 90% 아래에 머물 때만 한 번에 4단계까지 되돌린다. 화면 밖 여백은 폰과 같은 폭으로 줄여, 같은 상한으로 PC 화면 안 풀이 늘었다. 화면이 회전해 가로세로 합이 같아도 다시 그린다.
- `Village.resize`는 화면 높이를 잰 뒤 그림자를 맞춘다. 그림자 상자는 화면 가운데를 중심으로, 땅부터 인물 키(0.7)까지 보이는 부분을 그림자 카메라 축으로 재서 덮는다. 넓은 화면에서도 높이 3인 물체가 그림자 카메라 앞에 오도록 해의 거리를 늘린다.
- 원인은 독립 검토 3개로 반박해 보았다. 풀 상한 원인은 반박되지 않았다. 그림자는 처음 열 때는 정상이고 창 크기를 바꾼 뒤에만 틀린다고 바로잡혔다.
- 수정은 독립 검토를 두 차례 받았다. 1차 지적을 반영했다: 땅에만 맞춘 그림자 상자가 폰 화면 아래쪽 인물과 벽을 놓침, 64단계는 한 번에 바뀌는 풀이 많음, 회전 감지, 넓은 화면의 그림자 끝 잘림, 테스트가 오락가락을 못 잡음. 2차 지적도 반영했다: 줄인 여백 때문에 키 큰 풀이 PC 화면 위쪽 끝에서 늦게 나타남, 740×360 그림자 비용을 문서에 적지 않음.

### 확인
- 새 테스트 `nature-layer.test.ts`(5개), `light-rig.test.ts`(1개)는 수정 전 코드에서 실패하고 수정 후 통과한다. 수정을 하나씩 일부러 되돌린 7가지 변이(되돌림 여유 제거, 단계 매번 초기화, 가로세로 합 감지, 옛 산포 층, 땅에만 맞춘 그림자, 해 거리 고정, 옛 조명)를 모두 잡는다. `npm run typecheck`, `npm test`(207개) 통과.
- 헤드리스 Edge에서 수정본의 주인공을 9.5칸 걷게 하며 쟀다.
  - 1920×1080: 풀 5,578/5,600을 화면 전체에 고르게 그린다. 걷는 동안 바뀐 풀은 비교한 6만 8,658포기 중 1,282포기(1.9%)로, 풀이 적은 구역으로 가며 고르게 채워진 것이다. 그림자는 화면 끝의 땅과 높이 0.7까지 덮는다.
  - 1280×720: 풀 5,590/5,600, 바뀐 풀 3.3%, 그림자가 화면 끝을 덮는다.
  - 844×390(폰): 바뀐 풀 0. 화면 안 풀을 모두 그려 수정 전과 같다. 그림자 범위 4.88(수정 전 4.84).
  - 740×360(폰, 계산): 그림자 범위 4.26→4.51로 그림자 화소가 약 6% 굵어진다. 대신 수정 전에 놓치던 화면 끝과 인물 키 높이를 덮는다.
  - 844×390으로 연 뒤 1920×1080으로 키움: 그림자가 화면 끝을 덮는다. 수정 전에는 가장 먼 모서리가 그림자 범위의 2.87배 거리에 있었다.
- 미확인: 실기기, 사람 눈으로 본 PC 화면.
