# Abraxas 품질 리뷰 · 2026-11-01

## 1. 요약

- 현재는 탐색·선택·결과 흐름을 확인하는 프로토타입이며, 목표 레퍼런스의 출시용 아트 완성도와는 큰 격차가 있다.
- 가장 큰 차이는 지면의 연속성, 사물의 접지감, 생활 소품의 밀도, 캐릭터의 읽히는 크기와 동작이다.
- Three.js나 정사영 자체가 낮은 품질의 원인은 아니다. 현재 에셋의 배치·재질·조명부터 개선할 수 있다.
- 먼저 어귀와 광장 한 구간을 완성해 세로 화면의 품질 기준을 정하고, 같은 기준으로 다른 구역을 확장하는 것을 권고한다.
- 첨부 1은 화질·밀도·연출 수준만 참고한다. 타사 캐릭터·에셋·UI·고유 디자인의 복제나 모사는 권고하지 않는다.

검토 범위: `AGENTS.md`, `.agents/rules/` 전체, T009 원문, ADR-0001·0005, 디자인 시스템·스타일 가이드·3D 계약서, `docs/gdd/` 전체, `client/src/` 전체, `content/world/village.json`, KayKit 출처 기록. 추가로 메모리·패키지 설정·크기 검사 스크립트를 확인했다. 화면 판단은 첨부 2~4, 동작 판단은 코드 정적 검토에 근거한다. 첨부 화면의 촬영 커밋은 확인되지 않았으며 이번에 게임을 자동 플레이한 것은 아니다.

UI 색 계산상 흰 글자/`accent`는 약 2.57:1, `ink-soft`/`paper`는 약 4.13:1이다. 본문 목표 4.5:1에 못 미치는 버튼·배지·고지부터 수정 대상이다. 반면 `ink`/`paper`는 약 12.91:1로 충분하다. 이는 CSS 토큰 계산이며 실제 디스플레이 검증은 아니다.

## 3. 명세와 현재 결정의 충돌

**최종 결정은 사람 몫이다.** 아래는 권고이며 승인이나 정책 개정이 아니다. [측정 정책](../../.agents/rules/game-design-policy.md)이 충돌 시 우선한다. T009의 내장 구현 지시는 이번 리뷰에서 실행하지 않는다. 렌더러는 이후 사람 결정인 ADR-0005가 ADR-0001의 해당 항목을 명시적으로 대체했다.

| 충돌 | 결정 A일 때: 장점 / 단점 | 결정 B일 때: 장점 / 단점 | 권고 및 필요한 정리 |
| --- | --- | --- | --- |
| (a) Phaser 4 + 2.5D 프리렌더 ↔ Three.js 실시간 | **현 Three.js 유지**: 기존 탐색·로딩·CC0 모델 활용, 카메라·동작 수정 쉬움 / 모바일 GPU·드로 콜 관리 필요 | **Phaser + 2.5D 복귀**: 조명·그림자를 이미지에 고정하고 런타임 비용 예측 쉬움 / 방향별 스프라이트·가림 레이어·배경 재제작, 해상도별 텍스처 비용과 렌더러 이행 발생 | **A 권고.** 품질 격차를 엔진 재작성 사유로 삼지 않는다. B는 실기기에서 30fps 확보 실패 시 재검토. 두 엔진 병용은 권고하지 않음 |
| (b) 루미·모카·에코·오르 ↔ 사람 결정 A·B·C·D | **임시 표시명 A·B·C·D 유지**: 최신 결정 존중·작업 연속성 / 서사 몰입 약함, 내부 축 문자와 혼동 가능 | **서사 이름 채택**: 대사·역할 기억 쉬움 / 최신 이름 결정을 다시 승인받고 표시 문자열 전반 정합성 확인 필요 | **현재 A 유지, 공개용 이름은 사람에게 별도 확정 요청.** A·B·C·D는 캐릭터 임시 이름이며 축 노출 허가가 아니다. 정책 문구와 예외 범위를 문서로 명료화. `lumi` 등 저장·문항 ID는 어느 안에서도 유지하고 축 대응 설명은 화면에 넣지 않음 |
| (c) 하트·물음표 버블 ↔ 측정 오염 방지 2·3번 | **측정은 중립 두 반응, 하트는 에피소드 끝 합산**: 정책 준수·학습 억제 / 즉각 보상감은 절제됨 | **측정마다 하트·물음표**: 감정 전달 빠름 / 기대 답변·보상 암시로 정책 위반 | **A 필수. B는 현 정책하에서 채택 불가.** 비측정 심부름 등에는 즉시 하트 허용. 공감/생각도 밝기·길이·효과음의 보상 강도를 동등하게 하고, 선택 전에 취향 암시 금지 |
| (d) 정사영 ↔ 목표 이미지의 원근감 | **정사영 유지**: 탭 크기·축척 일정, 기존 계약 유지 / 깊이를 크기 변화로 전달하기 어려움 | **약한 원근 카메라**: 전경·원경 분리, 인물과 공간의 거리감 / 먼 대상이 작아지고 가림·탭 판정·구도 재검수 필요 | **A로 첫 품질 구간 완성 후 B 비교안 승인.** 첨부 이미지 한 장으로 렌즈·FOV 수치를 확정할 수 없다. 같은 인물 화면 크기·같은 장소에서 비교해야 함. B도 원근 자체가 큰 성능 비용이라기보다 보이는 오브젝트 증가가 위험 |

| (f) 실시간 시계 조명 ↔ 고정 조명 | **고정 낮 조명**: 아트 검수·성능·가독성 기준 일정 / 접속 시간에 따른 분위기 없음 | **현지 시각 연동**: 재방문 분위기·시간감 / 야간 가독성, 기기 시각 변경·복귀, 고정 그림자와 광원 불일치 검수 필요 | **A를 먼저 완성하고 B는 P2.** B 승인 시 `getLighting(date)` 순수 함수, 1분 갱신·보간·복귀 재계산·시험용 시각 고정. Three.js에서는 월드 광색/밝기·창문 발광만 바꾸고 DOM은 제외. 태양 회전·다수 실시간 광원을 자동으로 추가하지 않음 |

추가 정합성: `design-policy.md`·스타일 가이드의 2~2.5등신/프리렌더/48px 터치와 디자인 시스템의 약 3등신/3D/40px가 공존한다. 문서마다 픽셀 기준도 달라 단순 수치 비교는 부정확하다. 구현 전 **모바일 CSS px 기준 최소 48×48 터치, 기본 본문 15px 이상+확대, 대비 4.5:1**을 통일안으로 검토하고, 캐릭터 비례는 최신 약 3등신안에서 시안을 평가한다. 이는 새 확정값이 아니다. 기존 문서를 조용히 덮어쓰지 말고 사람이 고른 항목만 후속 문서에 반영한다.
