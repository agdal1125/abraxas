# RS1 생활 문제 통합 검수

2026-11-03 · 감독 Astra · PR #55 · 통합 검수 통과 · 최종 CI를 병합 조건으로 유지

루미의 축제 준비, 에코의 책 정리, 오르의 공방 일을 모카와 같은 서버 회차에 연결했다. 기존 장소 바깥의 작업판·물가·역할 NPC를 사용하며 새 실내나 큰 지형은 만들지 않았다. 세 주민의 운반·내려놓기·분기·수동/자동 퍼즐·마지막 보고, ko/en 대사와 소품 19종이 포함된다. 원래 문항·가중치·보상 수치·골든 파일은 변경하지 않았다.

## 역할과 통합

agy Argon4의 실제 요청이 429 한도를 반환해 사용자 지시대로 Codex CLI `gpt-6.1-terra`, xhigh, priority를 사용했다. C 계약 이후 S 서버·I 대사·N 통신·A 소품을 독점 파일로 병렬 진행하고 U 화면·W 월드·V 검증을 순차 통합했다. 각 패키지의 draft PR #47–#54는 검토 단위이며 단독 main 병합 대상이 아니다. Astra는 지시·검수·문서·저장소 관리와 직접 검증을, `gpt-6.1-sol`은 독립 코드 검수를 담당했다.

구현자는 관리 worktree의 workspace-write와 네트워크 비활성 설정을 유지했다. 부모의 상위 환경 사용은 승인된 로컬 검증·저장소 관리에 한정했다. 비밀값 읽기, 전역 설정·ACL 변경, 실제 Firebase 프로젝트와 배포는 하지 않았다.

## 직접 실행 증거

모든 E2E는 감독이 직접 실행했다. 아래 경로는 통합 worktree의 `.e2e/` 아래 원본 캡처와 JSON이다. 확인된 실행의 공유용 JSON은 [rs1 증거 폴더](rs1/)에 보존했다. 에뮬레이터는 Auth·Firestore의 `demo-abraxas`만 사용하고 Edge 자체 샌드박스와 임시 프로필을 유지했다.

완료한 여섯 실행은 결과 화면·종료 코드 0·예상 밖 HTTP 응답 0건을 확인했다. `interactTarget` 개발 훅으로 대부분의 목적지를 지정하되 순간이동이나 도착 콜백 직접 실행 없이 실제 자동 이동·도착을 기다렸다. 별도로 주민당 최소 한 번 CDP 마우스 입력을 사용했고 한국어 b-manual에서는 이를 터치로 검증했다. 모든 대상의 실제 터치를 검사한 것은 아니다. 바구니의 지면 기준 화면점은 적중하지 않아 그 점을 건너뛰고 다른 유효한 모카 대상으로 포인터 도착을 확인했다. DOM 퍼즐·대사 버튼은 자동화 클릭을 사용했다.

`resume`은 세 주민 각각 선택 확정·임시 내려놓기·퍼즐 일부 배치·완료 응답 적용 뒤 새로고침해 같은 회차·revision·답·물건·배치·완료 목록과 대기 명령 제거를 확인한다. 보고 응답의 네트워크 유실은 브라우저에 주입하지 않았다. 해당 유실·동시성·동일 명령 재전송은 HTTP·통신·Firestore 테스트가 주 증거다.

## 자동 검사와 검수 수정

- 감독 실행: 클라이언트 typecheck·143개 테스트·build·check:size 7.16 MiB/10 MiB·npm audit 취약점 0건. 서버 gofmt 출력 없음·vet·test·govulncheck 통과. 호출된 취약점과 import 패키지 취약점은 0건이며 사용하지 않는 모듈 취약점 3건이 보고됐다.
- Firestore fake 트랜잭션과 실제 로컬 에뮬레이터의 재시도·같은 revision 경쟁·중복 완료·응답 유실 검증 통과. 통합 서버에서 에뮬레이터 스크립트도 재실행해 종료 코드 0을 확인했다.
- 12개 도달성 시나리오, 에셋 검사(총 695,248바이트·오류 0), 표시 이름, 세 주민 18문항의 원문·선택지·대사 knot 검사 통과. 기존 측정 JSON과 골든 파일은 기준 `271be63`과 diff가 없다.
- 서버에서 네 주민의 24가지 완료 순서와 주민별 64개 답 조합을 검사했다. 각 조합은 수동·자동 퍼즐·운반 중 내려놓기 경로에서 여섯 답·완료 사건 한 건·기존 보상과 전체 계산 결과가 같았다. 유형 계산의 나머지 답은 기존 골든 로그에서 채웠으며 24×64개의 전체 브라우저 플레이를 했다는 뜻은 아니다.
- Sol이 발견한 같은 대기 요청의 동시 복구 오류를 수정했다. 먼저 끝난 복구가 이미 대기 기록을 지웠으면 두 번째 복구도 성공하고, 다른 회차·키는 보존한다. 저장소 접근 실패는 계속 보고한다. 집중 회귀 테스트가 통과했다. 후속 Sol 재검수에서도 새 P1/P2가 없었고 관련 39개 테스트가 통과했다.
- 감독이 발견한 숨긴 소품의 보이지 않는 충돌 영역을 실제 가시 상태로 재계산하도록 수정했다. 소품 로드 실패는 다음 시도에서 복구할 수 있다.
- 대사 파서의 모든 생성 경로를 지연 로드하며 실패 후 재시도와 오래된 응답 차단을 유지했다. 작업판에는 일반 대사창의 높이 제한이 적용되지 않도록 선택자 우선순위를 수정하고 한국어 단어 중간 줄바꿈을 줄였다.

## 화면·디자인과 한계

3dviz 적응 스킬과 [캐릭터·NPC 개선 제안](../design/character-npc-polish-plan.md)은 PR #45에 포함됐다. 공식 자료 기반 정성 비교이며 직접 플레이나 수치 성능 벤치마크는 아니다. 이번 소품과 배치는 역할 도구·작업 장소·상태가 함께 읽히는지 실제 게임 화면으로 검토했다. 주역 실루엣·의상 연결·공유 NPC 외형의 별도 개선은 사람 승인 대기이며 제작하지 않았다.

한국어 resume은 12개 재개 지점, 네 주민 × 4개 해상도 × 15/18px 글자 크기의 32개 조합에서 가로 넘침 0·48px 이상 버튼·스크롤 뒤 닫기 접근 및 Tab 이동을 확인했다. 영어도 동일한 12개 재개 지점과 32개 조합을 통과했다. 두 언어 합계 24개 재개·64개 화면 조합이다. [영어 740×360 확대 글자](rs1/en-viewport-echo-740x360-18.png)도 보존했다. [루미 작업판](rs1/ko-board-lumi.png), [에코 작업판](rs1/ko-board-echo.png), [오르 작업판](rs1/ko-board-or.png), [740×360 확대 글자](rs1/ko-viewport-lumi-740x360-18.png), [오르 보고](rs1/ko-report-or.png)를 보존했다. 실기기 iOS Safari·Android·카카오톡 인앱, 회전·두 손가락 입력·실측 소요 시간은 확인하지 않았다. 실제 App Check 공급자·운영 배포·장기 저장과 Docker 이미지 실행도 이번 로컬 검증 범위에 포함하지 않는다. Docker 실행 도구가 없어 루트 빌드 컨텍스트와 콘텐츠 경로는 정적으로만 검토했다.

로컬 Go는 CGO_ENABLED=0이고 C 컴파일러가 없어 race 모드는 실행하지 않았다. 일반 테스트의 명시적 동시 요청·트랜잭션 경합 검사는 통과했다.

제품 통합 커밋 `6ef213f`의 [CI 41476481904](https://github.com/agdal1125/abraxas/actions/runs/41476481904)는 macOS·Windows·Linux 포함 전체 성공했다. 문서·증거를 포함한 최종 커밋도 [PR #55 검사](https://github.com/agdal1125/abraxas/pull/55/checks)가 모두 성공한 뒤 main에 병합한다. 지정 Notion 개발 일지 데이터베이스는 404여서 저장소 일지만 갱신한다.
