## 변경과 검수

- 루미·에코·오르 상태를 필수로 읽고 계약 JSON의 단계, 물건과 위치, 퍼즐 조각과 자리, 답 순서 및 완료 상태를 검증한다. 네 주민의 운반 물건은 합쳐서 하나만 허용한다. 완료 표시 `episodeEnd`는 해당 주민의 완료 상태와 대조한다.
- `place_piece` 대기 명령을 검증하고 복구한다. 다른 키의 영수증은 최신 스냅샷이 같은 문항의 같은 답이나 같은 대상의 완료를 증명할 때만 허용하며, 대기 기록은 재전송에 사용한 키로 정리한다. 영수증의 적용 revision은 최신 스냅샷보다 오래될 수 있지만 스냅샷의 역행과 잘못된 반응 종류는 거부한다.
- 기존 모카 상태·완료 검증과 같은 키의 명령 충돌을 유지한다. 세 주민의 수동·자동 경로 fixture와 모카 fixture, 잘못된 상태·영수증·복구 사례를 검사했다.

## 남은 통합과 제한

- 현재 기준 서버는 새 주민 상태를 아직 반환하지 않는다. RS1-S의 응답·의미상 중복 완료와 RS1-V의 실제 HTTP 통합 검증이 필요하다. 모의 응답 테스트는 서버의 원자적 저장이나 보상을 증명하지 않는다.
- UI·월드·ink·실기기·배포·실제 인증은 이번 범위 밖이며 검사하지 않았다. 콘텐츠 버전 연결도 RS1-V 범위다.
- 공용 기억과 개발 일지는 독점 쓰기 범위 밖이므로 병합 담당자에게 인계한다. 커밋·병합은 하지 않았다.
