## 구현

서버 회차에서 루미·에코·오르는 확정된 단계의 활성 월드 대상과 명령으로 진행한다. 선택지는 각 주민의 ink knot를 열고 서버 응답의 반응을 표시한다. 받침대 운반, 분기 행동, 마지막 보고와 서버 완료 응답을 연결했다. 기존 로컬 루미 연속 이야기와 로컬 저장 흐름은 유지한다. 작업판은 서버가 확정한 배치만 복원하고 조각·자리의 주제, 힌트, 자동 배치와 반복 입력 방지를 제공한다. 오르 등불은 단일 연결 명령이다. 결과 계산에는 서버가 확정한 네 주민의 완료 목록을 전달한다.

## 월드 연결 계약

`Village`에는 다음 필수 메서드가 필요하다. UI는 선택적 대체 구현 없이 호출하므로 RS1-W를 병합한 뒤 실행해야 한다.

- `setLumiView(view: ReturnType<typeof lumiView> | null): void`
- `setEchoView(view: ReturnType<typeof echoView> | null): void`
- `setOrView(view: ReturnType<typeof orView> | null): void`
- `resumeLumi(): Promise<void>`, `resumeEcho(): Promise<void>`, `resumeOr(): Promise<void>`

네 주민의 `set*View`는 모든 유효한 서버 스냅샷마다 잠김·진행·완료 상태를 포함해 모두 호출된다. 신규 주민 뷰의 `objects`, `placements`, `choices`, `resumePointId`와 완료 단계를 사용해 현재 소품과 이미 완성한 장식을 유지한다. 재개 메서드는 활성 주민의 서버 뷰를 받은 다음 호출되며 안전한 재개 위치를 선택한다. 재시작과 로컬 체험 진입은 네 뷰에 `null`을 전달한다. 상호작용은 기존 `onInteract(targetId)`로 전달한다.

## 검증과 남은 범위

- 클라이언트 집중 테스트: 2개 파일, 7개 통과. 전체 `npm test`: 24개 파일, 115개 통과. `npm run typecheck`와 `npm run build` 통과. 빌드는 런타임 폰트 경로와 큰 번들 경고를 출력했다.
- 서버 `go vet ./...`, `go test ./...`는 로컬 도구체인과 `.e2e/go-cache`, 네트워크 비활성 설정에서 통과했다. `govulncheck`는 실행 파일이 없어 실행하지 못했다.
- fixture 양쪽 경로에서 행동 대상과 명령 종류를 대조하고 받침대, 서버 배치 복원, 반복 입력, 잠김·완료 뷰 전달을 검사했다. 이는 서버를 경유한 전체 UI 동작이나 네 주민의 모든 실제 순서를 증명하지 않는다.
- RS1-W 월드 병합 전에는 필수 메서드가 없어 서버 회차가 실행되지 않는다. 실제 브라우저·회전·터치·키보드·실기기와 전체 막간·축제·재접속 E2E는 감독 및 RS1-V 검증 범위다.
