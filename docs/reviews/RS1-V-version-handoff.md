# RS1-V 콘텐츠 버전 인계

2026-11-02 · 초기 콘텐츠 버전 범위. 사용자 지시에 따라 agy의 지속 429 한도 이후 대체 구현했다. 요청된 모델은 `gpt-6.1-terra`, 추론 `xhigh`, priority이며 이 실행에서 실제 모델과 서비스 우선순위는 독립적으로 확인하지 못했다.

`scripts/content-version.mjs`의 필수 해시 입력에 루미·에코·오르 계약 JSON을 추가했다. 모카와 기존 측정 JSON, 양 언어 번역·ink의 정렬 및 원본 바이트 해시 방식은 유지한다. 새 계약이 없으면 파일 읽기 오류로 실패한다. 선택지·가중치·보상·서버 판정은 변경하지 않았다.

- `node --test scripts/content-version.test.mjs`: 4개 통과. 독립 임시 자료에서 세 계약 각각의 변경과 누락, 기존 입력 전체, 반복 계산 및 LF/CRLF 바이트 차이를 확인했다. 구현 전에는 세 계약 변경이 반영되지 않아 실패했다.
- 현재 콘텐츠 해시를 계산하고 Vite 설정의 `__CONTENT_VERSION__`과 대조했다. 일치했다. `go -C server test ./internal/play -run 'TestMokaFixtures|TestLumi' -count=1`도 통과해 현재 콘텐츠를 서버 엔진이 읽는 경로를 확인했다. Go는 로컬 도구체인과 `.e2e/go-cache`를 사용하고 네트워크를 껐다.
- 서버는 자체 해시를 계산하지 않고 `ABRAXAS_CONTENT_VERSION`을 전달받는다. E2E 스크립트는 같은 해시 함수를 서버 환경에 전달한다. 현재 해시를 전달한 서버 프로세스의 시작 검사는 완료 결과를 받지 못해 중단했으므로 실제 런타임 주입 일치는 아직 확인하지 못했다. 프로세스 확인을 위한 Windows CIM 조회는 접근 거부됐다.

`server/Dockerfile`의 최종 이미지는 바이너리만 복사하므로 신규 세 계약을 포함한 콘텐츠 전체가 없다. 서버 기본 콘텐츠 경로에는 파일이 제공되지 않으며 버전 환경값도 별도 주입이 필요하다. Docker 변경은 이 초기 작업의 쓰기 범위 밖이므로 통합 담당자가 빌드 컨텍스트와 콘텐츠·버전 전달을 함께 해결해야 한다. 배포·설정은 변경하지 않았다.

E2E, 실제 인증·저장, 브라우저와 전체 제품 검사는 이번 범위에서 실행하지 않았다. E2E 스크립트, git 작업, CI, 공유 기억과 개발 일지는 부모 작업에 인계한다. 클라이언트 의존성은 지정된 기존 설치본에서 삭제 없이 복사했다.
