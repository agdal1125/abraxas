# 플레이테스트 기록 양식

이 파일을 복사해 `docs/qa/playtests/YYYY-MM-DD-<기기>-<별칭>.md`로 저장한다. 저장소가 공개이므로 실명, 연락처, 익명 uid, 토큰은 쓰지 않고 별칭만 쓴다.

## 진행 규칙

- 플레이 전에 측정 구조, 유형 수, 축 이름, 호감도 규칙을 설명하지 않는다. "선택에 따라 결과가 달라지는 이야기"라고만 소개한다.
- 플레이 중에는 답을 알려 주거나 선택을 평가하지 않는다. 완전히 막혀 도와줬다면 그 위치와 내용을 기록한다.
- 확인하지 못한 칸은 비워 두지 않고 `[?]`로 적는다. `[ ]`는 할 일이 남았다는 뜻이고, `[?]`는 아무도 확인하지 못했다는 뜻이다.

## 측정 오염 관찰

정답을 찾는 행동은 결과의 신뢰도를 떨어뜨린다. 답을 고른 이유를 묻지 말고 행동을 관찰해 적고, 질문은 플레이가 끝난 뒤에만 한다.

- NPC 반응을 맞았다, 틀렸다로 받아들인 순간:
- 호감을 얻으려고 답을 고르는 말이나 행동:
- 선택을 되돌리려는 시도(새로고침, 뒤로 가기):
- 선택지 문구, 순서, 데미의 움직임에서 정답 암시를 느낀 곳:
- 화면에 내부 코드, 성향 수치, 호감도 숫자가 보인 곳:

## 결과와 다시 하기

- 결과를 보고 "내 모습 같다"고 느낀 정도: 1 / 2 / 3 / 4 / 5
- 가장 맞다고 한 문장:
- 가장 아니라고 한 문장:
- 고지 문구를 봤나: 예 / 아니오
- 고백 상대와 이유가 이야기로 납득되었나: 예 / 아니오 / 일부
- 친구에게 공유하고 싶은가: 예 / 아니오 / 글쎄, 이유:
- 다른 선택으로 다시 하고 싶은가: 예 / 아니오 / 글쎄, 이유:

결과 평가는 플레이 경험 기록이며 성격 측정의 타당도 근거로 쓰지 않는다.

## 버그

충돌, 진행 불가, 프레임 저하처럼 분명히 고장 난 것은 위 "답답했던 곳"이 아니라 여기에 적는다.

| 번호 | 구간 | 내용 | 심각도 | 재현 | 스크린샷·로그 |
| --- | --- | --- | --- | --- | --- |
| 1 | | | 치명 / 높음 / 중간 / 낮음 | 항상 / 가끔 / 1회 | |

심각도 기준은 다음과 같다.

- 치명: 진행 불가, 저장 손실, 선택 재시도 가능, 내부 값 노출
- 높음: 우회는 되지만 대부분의 플레이어가 겪음
- 중간: 일부 기기나 경로에서 겪음
- 낮음: 외관 문제
