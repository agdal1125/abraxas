# 그래픽 완성도와 플레이 몰입 정책 — T018-P1

2026-11-05 · 정책 설계: Codex `gpt-6-astra`, reasoning `high` · 검수: Claude(2026-11-05, 문서 대조만 수행, 게임 실행 검증 아님).
**사람 검토용 제안이다. 제품 코드·애셋 변경, 방향 승인, 성능 합격을 뜻하지 않는다.** 이번 산출물은 이 문서 하나이며 구현은 마지막 질문의 결정과 한 화면 시제품 검토 뒤 진행한다.

> **2026-11-05 사람 결정으로 갱신:** A안을 고른 뒤 시제품을 본 사람이 저폴리 디오라마 표현으로 더 깎으라고 지시했다. 환경은 면이 보이는 플랫 셰이딩, 재료 색, 부재 단위 형태, 또렷한 빛으로 간다(`docs/tasks/T018-P3-faceted-direction.md`). 이 문서의 '둥근 형태'와 '차분한 환경' 표현은 환경에 대해 이 결정이 우선한다. 소리와 시간 변화는 아직 하지 않았다.

## 1. 목표와 적용 우선순위

도리마을은 **누군가 오늘 빵을 굽고, 책을 정리하고, 축제를 준비한 흔적이 남은 작은 마을**로 보인다. 둥근 형태는 유지하되 벽·목재·천·껍질의 경계와 쓰임을 실제 게임 크기에서 읽게 한다. 약 30분 동안 걸으며 사람을 알아가는 경험이므로 작은 생활 반응과 분명한 길찾기가 장식량보다 우선한다. 성별 중립, 약 3등신, 인물별 선명한 대표색, 얼굴 없는 흰 알 껍질 주인공, 정사영 쿼터뷰를 유지한다. 환경은 인물보다 차분하게 두며 특정 게임의 이름·캐릭터·에셋·외관을 복제하지 않는다.

- 최우선은 [측정 무결성](../../.agents/rules/game-design-policy.md). 성향·문항·호감도·초대권 수치와 선택 저장 규칙은 이 정책의 변경 대상이 아니다.
- 정체성은 [디자인 시스템](design-system.md)과 [캐릭터 개선 계획](../design/character-npc-polish-plan.md)을 따른다. [옛 스타일 가이드](style-guide.md)의 2~2.5등신·점 눈 주인공·외부 폰트 지시는 채택하지 않는다.
- 현행 렌더링은 `village.ts`의 Three.js다. 문서의 옛 KayKit·헥스 배치 설명보다 현행 GLB·manifest·월드 v2를 구현 근거로 삼는다.
- [환경 밀도 문서](quality-environment.md)의 구역별 생활 의도는 재사용한다. “빈 땅 없이 고르게 채우기”와 장식 개수만으로 합격시키는 방식은 본 제안 승인 후 대체한다. 정책 간 충돌은 승인 시 감독이 기존 문서에 반영한다.

## 2. 비평을 실제 문제로 분리한 결과

[사용자 원문](../tasks/T018-user-brief.md)과 [첨부 화면](../reviews/immersion/2026-11-05-user-screenshot.webp)을 직접 읽고 보았다. 아래 원인 중 실행 화면 재현이 필요한 것은 가설로 남긴다.

| 비평·후보 | 확인된 사실과 수정할 진단 | 우선 조치와 판정 |
| --- | --- | --- |
| 길이 집보다 날카롭다 | 화면의 급한 꺾임은 확인된다. `build_terrain.py`는 길 메시를 따로 놓기보다 선분 거리와 정점 색으로 길을 칠한다. 월드의 길 51개는 모두 폭 0.9이고, 가장자리 흐림과 중앙·가장자리 색 파동은 이미 있다. 따라서 “아무 변화 없음”은 틀리고, 일정 폭의 꺾인 중심선과 낮은 해상도의 형태가 문제 후보다. | 모서리 흐림을 더하기 전에 시제품 구간 중심선을 완만하게 잇고 폭·가장자리 침범을 조정한다. 실제 이동 가능한 통로와 보이는 길이 일치해야 한다. |
| 집이 블록 장난감 같다 | 첨부에는 빈 옆·뒷벽, 넓은 단색 지붕, 정체가 모호한 노란 덩어리가 보인다. 그러나 생성기에 창·처마·굴뚝·차양이 있고 `bakery-before-after.png` 정면에는 창틀·문판도 보인다. “창문·처마가 전혀 없음”은 틀리다. 현행 빵집 두 채는 회전값 3.142와 2.094로 놓여 있다. 화면과 동일 상태의 정면 노출 여부는 실행 검증 대상이다. | 먼저 입구·진열창이 접근 방향과 카메라에 보이게 한다. 그다음 실제 보이는 벽과 지붕에 큰 재질 단서를 더한다. 모든 집의 연기·기와 추가를 의무화하지 않는다. |
| 큰 천·노란 곡면이 무엇인지 안 읽힌다 | 빵집 생성기의 줄무늬 차양과 노란 원통형 부품은 확인되나, 화면에서 이것이 빵 간판인지 차양인지 즉시 읽히지 않는다. | 차양은 지지대·벽 접합·드리운 그림자, 빵 간판은 빵 형태와 고정점을 갖춘다. 축소 화면에서 읽히지 않는 큰 부품은 크기를 키우기보다 단순화하거나 제거한다. |
| 느낌표가 세계와 떨어져 보인다 | `Village.label()`은 노란 원에 `!`를 그린 2D 스프라이트다. 머리 위에 부착되어 있어 위치 연결은 존재한다. 독립된 UI 색·모양이 생활 소품보다 먼저 보이는 점이 문제다. | 진행 정보는 유지하되 가까이서 대상에 붙은 작은 표식과 발밑 표시로 연결한다. 감정이나 정답 표시로 쓰지 않는다. |
| 주인공이 흰 자리표시자 같다 | `whitenPlayer()`는 복제한 정점 색의 RGB를 모두 1로 만든다. 캐릭터 생성기는 AO를 정점 색에 곱하므로 이 색·AO 정보가 소실된다. 모델 형상과 실시간 그림자는 남아 있으므로 “그림자 전체 소실”은 아니다. 프리뷰의 껍질 경계와 게임의 백색 덩어리 차이가 이를 뒷받침한다. | 흰 정체성을 유지하면서 명암·껍질 경계를 보존하는 방식으로 교체한다. 원래 베이지 프리뷰로 단순 복귀하는 것은 목표가 아니다. |
| 저폴리 연옥·균일한 빈 공간 | 첨부에는 작은 꽃·상자·통나무가 흩어지고 역할의 중심이 약하다. 지면에는 이미 색 파동, 조명에는 반구광·방향광·그림자, 효과에는 꽃잎·반딧불·안개·발광이 있어 “완전 단색·조명 없음”은 틀리다. 현행 `place()`는 배치별 객체 복제이며 옛 문서의 590개 인스턴스 장식 구조가 아니다. | 전역 채우기보다 작업장·정원·길목에 군집을 만들고 통행 공간을 비운다. 광원·효과 추가보다 기존 밝기와 접촉 명암을 먼저 비교한다. |
| 추가 문제: 제작 프리뷰와 플레이 구도 차이 | 환경 생성기는 현재 `bakery`, `tree-round`, `bush`만 GLB·개별 프리뷰를 내보내고 나머지는 건너뛴다. 전체 blend 재구성과 배포 GLB 갱신 범위가 다를 수 있다. Blender 프리뷰의 조명도 게임과 다르다. | 납품마다 대상 GLB·생성기 리비전·프리뷰 출처를 함께 기록한다. 확대된 정면 프리뷰를 실제 화면 합격의 대용으로 쓰지 않는다. |

첨부의 빨간 대사창 표시는 시각 근거로만 취급한다. 글자 깨짐 수정은 별도 T018-F1 범위이며 여기서 문항이나 문구를 고치지 않는다.

## 3. 그래픽 방향 비교와 추천

비용은 상대적인 제작·검수 규모이며 실제 견적이나 측정된 프레임 영향이 아니다.

| 후보 | 목표 인상 | 비용 | 모바일 영향 가설 | 기존 자산·생성기 재사용 | 실패 위험 |
| --- | --- | --- | --- | --- | --- |
| **A. 현행 저폴리의 형태·배치·명암 정리 — 추천** | 손으로 만든 작은 생활 공간. 재료와 용도가 분명한 둥근 마을 | 중간. 한 화면으로 효과를 먼저 판단 가능 | 정점 색·공유 모델을 유지하면 전송 증가를 억제할 여지가 있다. 배치·그림자 드로 콜은 별도 측정 | GLB 계약, 리그, 대부분 모델, Blender 생성기와 Draco 경로 유지 | 세부만 늘리고 빈 면·구도·반복을 방치하면 현재 인상이 남음 |
| B. 손그림 텍스처 중심 | 붓 자국과 표면 질감이 있는 그림책 마을 | 큼. UV·아틀라스·색공간·축소 가독성 작업 추가 | 텍스처 전송·GPU 메모리·샘플링 비용 증가 가능. 메쉬 감소 효과는 미측정 | 실루엣·리그 일부 유지, 현행 정점 색 파이프라인은 보완 필요 | 흐릿한 텍스처가 작은 화면에서 얼룩처럼 보이고 광원과 중복 음영 발생 |
| C. 아트 전면 교체 | 조형 언어부터 재설계한 새로운 마을 | 매우 큼. 전 자산·충돌·리그·일관성 재검수 | 구현 방식에 따라 달라 현재 예측 불가 | 월드·진행 데이터 일부만 유지, 현행 GLB 대부분 재작업 | 이미 만든 콘텐츠와 정체성이 흔들리고 30분 체험 개선이 지연 |

**A로 빵집 앞 한 화면을 먼저 만든다.** 현재 생성기는 베벨, 창틀, 처마, 부품 결합, 정점 색과 AO를 이미 처리하므로 큰 형태·재료 경계 개선에는 사용할 수 있다. 반면 색을 조금 바꾸고 프리미티브를 추가하는 자동 생성만으로 생활감과 일관된 구도를 보장하지 못한다. 제작자가 실제 카메라 크기로 실루엣과 배치를 고쳐야 한다. 손그림 품질은 현행 파이프라인만으로 낼 수 있다고 약속하지 않는다. A 시제품이 두 차례 구도·조형 수정 뒤에도 목표 인상에 못 미치면 전면 확장을 멈추고 B의 한 건물 표면 시제품 필요 여부를 사람에게 제시한다.

## 4. 화면에서 판정하는 규칙

아래 수치는 모두 **승인 전 제안 기준**이다. 검사 단위는 별도 표기가 없으면 740×360 CSS px와 844×390 CSS px의 정상 플레이 화면이다. 확대 이미지·개수 충족만으로 통과시키지 않는다.

| 대상 | 규칙 | 불합격 사례 |
| --- | --- | --- |
| 지면·길 | 가까운 굽이에는 직선 두 개가 꺾여 만나는 뾰족한 외곽을 남기지 않는다. 기본 폭 0.9를 기준으로 시제품 시각 폭은 0.8~1.1 범위에서 완만히 바꾼다. 가장자리 풀·돌은 폭의 15% 이내로만 들어오고 통행 중심은 비운다. | 흐린 테두리 아래 각진 중심선이 그대로 보임, 길처럼 보이는 곳이 충돌로 막힘 |
| 지면 질감 | 한 화면에 넓은 풀 색면·밟힌 길·건물 또는 나무 밑 접촉부의 세 층이 보인다. 길에는 한 종류의 생활 흔적만 선택한다(발에 닳은 가장자리 또는 작업터 흔적). 작은 돌·바퀴 자국을 모든 곳에 뿌리지 않는다. | 노이즈만 증가, 풀과 길이 같은 밝기로 섞임, 미세 무늬가 이동 중 반짝임 |
| 건물 | 빵집=진열창·빵, 도서관=책·독서 자리, 대장간=모루·작업대, 광장=무대·준비물 중 역할 단서 2개를 실제 접근 화면에 노출한다. 입구로 이어지는 바닥과 문이 보이고, 보이는 큰 벽에는 창·목구조·걸린 도구 중 하나가 있다. | 이름표를 가리면 역할을 구별하지 못함, 정면 디테일이 카메라 반대편에만 있음 |
| 지붕·천 | 지붕과 벽은 처마 두께·아랫면 명암으로 구분한다. 기와·널판은 게임 화면에서 2px 이상 읽히는 큰 구획만 쓴다. 차양은 벽 고정점과 앞단을 갖추고 간판은 지지 구조를 보인다. | 장난감 판 한 장처럼 떠 있는 지붕, 역할을 설명해야 이해되는 큰 노란 덩어리 |
| 소품 반복 | 같은 소품·같은 크기·같은 방향(회전 차 15° 미만)이 한 화면에 3개를 넘지 않는다. 빵 상자는 빵집 작업 영역에, 통나무는 작업터·숲 가장자리에 2~4개 군집으로 모으고 무관한 빈 땅에서는 줄인다. 의도된 울타리·구조 부재 반복은 제외한다. | 랜덤 회전만 주고 같은 물건을 등간격 살포, 역할과 무관한 빵 상자 반복 |
| 나무·식생 | 한 화면에 나무 또는 관목의 큰 실루엣 2종을 섞되 모든 화면에 나무를 채우지 않는다. 밑동·뿌리와 식생이 접지되고 작은 꽃은 2~3곳의 군집으로 묶는다. 대화자·손의 작업물·목표까지 이어지는 통로를 수관이 가리지 않는다. | 인물 앞에 동그란 수관이 겹침, 발밑 풀로 껍질·도구가 가려짐 |
| 조명·그림자 | 현재 방향광 1개를 유지한다. 얼굴 없는 주인공에서도 윗면·옆면·접촉부가 구분되도록 반구광과 방향광 비율을 조절한다. 움직임 전후 발·밑동·기둥 그림자가 붙어 있고 AO는 한 번만 적용한다. | 전 화면 뿌연 밝기, 몸이 순백으로 뭉침, 겹친 AO가 검은 테두리처럼 보임 |
| 하늘·안개·시간 | 쿼터뷰 구도를 유지하며 빈 하늘을 채우려고 카메라를 기울이지 않는다. 안개는 먼 배경에만 쓰고 현재 상호작용 거리의 인물·길 대비를 깎지 않는다. 시간 변화는 에피소드 진행에 따른 낮→축제의 따뜻한 빛→문 앞의 고요함으로 제한한다. | 상시 안개로 낮은 조형 품질을 가림, 문항 응답 직후 특정 색이 강해짐 |
| 주인공 | 흰 바탕 안에서 껍질의 깨진 가장자리·몸통·팔다리 연결과 발 접촉이 읽힌다. 얼굴을 추가하지 않고 피부색·성별 단서를 주지 않는다. 색을 흰 계열로 옮겨도 원래 음영 차이를 보존한다. | 전체 정점 RGB를 같은 값으로 덮음, 그림자·경계를 복원하려다 검은 윤곽선으로 둘러침 |
| 진행 표식 | 작은 `!`는 진행 가능 여부만 뜻한다. 가까운 표식은 대상 머리와 4~12px 간격을 두고 18~24px 크기를 시제품에서 비교한다. 실제 터치 영역은 최소 48×48px로 별도 확보한다. 대화 중 화자 위 표식은 숨기고, 여러 대상이 있으면 모두 같은 규칙을 적용한다. | 특정 NPC나 답에만 강한 반짝임, 표식을 줄이면서 목표가 사라짐, 색만으로 진행 여부 전달 |
| 카메라 | 정사영·35° 쿼터뷰와 현행 주인공 약 70px 투영 높이를 출발점으로 삼는다. 두 화면 크기 모두 이동 중 머리·발이 보이고 대화 중 화자·주인공·작업물이 대사창 위에 남는다. 줌·회전 조작은 추가하지 않는다. | 넓게 보여주려고 인물을 축소, 클릭 때 갑작스러운 구도 점프, 이동 흔들림 |
| UI | 기본 글자 크기의 정상 가로 대화에서 UI 점유율 40% 이하, 본문 17px(T018-F1)·대비 4.5:1 이상, 터치 높이 48px를 유지한다. 큰 글자 20px 설정에서는 가독성을 우선하고 긴 선택지는 기존 스크롤로 모두 접근한다. 모든 선택지의 폭·색·강조 수준을 같게 한다. | 점유율을 맞추려 큰 글자를 축소, 한쪽 선택지만 강조, 선택지 잘림, 대화 넘기기 탭이 이동으로 전달 |

목표 지점 주변의 빈 공간은 실패가 아니다. “인물의 동작 공간, 이동 통로, 다음 목적지를 보이는 여백” 중 이유를 설명할 수 있으면 남긴다.

## 5. 약 30분 체험에 맞춘 플레이 몰입

현행 수동 이동·대상 탭 자동 접근·도착 표시·근접 링·대화 시 마주보기·작업물 상태 변화를 재사용한다. 아래는 그 위에 더할 최소 제안이며 아직 구현됐다는 뜻이 아니다.

| 경험 | 최소 제안과 수락 조건 |
| --- | --- |
| 이동 손맛 | 터치 입력 후 두 렌더 프레임 안에 이동 또는 탭 표시를 보여준다(로딩 중 제외). 수동 입력은 자동 접근을 즉시 취소하고 손을 떼면 미끄러지지 않는다. 기존 보행 속도·거리 기반 애니메이션을 유지해 발 미끄러짐만 조정한다. 새로운 달리기·스태미나·실패 페널티는 없다. |
| 걸으면 생기는 일 | 발걸음 소리를 실제 이동에 맞춰 내고 정지·벽에 막힘·대화 중에는 멈춘다. 추가 먼지·발자국 입자는 첫 시제품에 넣지 않는다. 현재 꽃잎·반딧불 수를 늘리기보다 필요한 장소에 보이도록 조절한다. |
| 세계 반응 | 말을 걸면 NPC가 플레이어를 바라보고 현재 작업 동작을 잠시 멈춘다. 기존 심부름에서 빵·책·도구를 받거나 놓는 상태가 손과 작업대에 맞게 보인다. 성공 여부·답의 극에 따라 조명·식생·표정의 질을 달리하지 않는다. |
| 소리 | 첫 후보는 발걸음 1종과 빵집 또는 광장의 환경음 1종이다. 사용자 입력 뒤 재생을 시작하고 설정에서 음소거하며 무음으로도 동일하게 진행한다. 동시 재생 최대 3개, 앱 비활성화 시 정지. 선택 평가용 성공·실패 음은 넣지 않는다. 현행 코드 검색에서는 영상 음소거 UI만 확인했으며 월드 사운드 시스템은 확인되지 않았다. |
| 시간 흐름 | 실제 시계·응답 속도 대신 저장된 챕터 상태로 조명과 환경음 상태를 정한다. 재접속 시 같은 장면을 복원하고 대화가 끝난 경계에서 부드럽게 전환한다. 기다림·야간 시야 제한·새 시간제 퀘스트는 없다. |
| 탐색 보상 | 기존 `examine` 대상의 짧은 생활 묘사를 발견 보상으로 쓴다. 별도 수집물·숨은 능력치·추가 기억 조각은 만들지 않는다. 읽지 않아도 기존 31분 흐름과 38+4 문항이 그대로 진행된다. |
| 환경 유도 | 빵집 입구와 진열품, 도서관 책장, 대장간 작업대가 길에서 보이고 갈림길의 표지판은 장소를 가리킨다. 표식을 임시로 숨긴 검수에서 새 관찰자 3명 중 2명이 5초 안에 목적지 방향을 짚어야 한다. 실제 플레이에는 진행 표식을 남겨 길찾기를 돕는다. |
| 장면 전환 | 대화 진입·종료에 이동 입력이 새지 않게 하고 화자 쪽으로 기존 카메라를 이동시킨다. 추가 비필수 전환은 0.3초 이내를 목표로 하며 움직임 줄이기 설정에서는 흔들림·부유·장식 입자를 끈다. 원래 프렐류드·결말 영상은 재제작하지 않는다. |

**측정 오염 금지 목록**

- 선택 전 NPC의 기대 답을 시선·몸짓·장소 색·소리·데미의 선행 방향으로 암시하지 않는다. 측정에서 두 경로 중 어느 쪽이 더 따뜻하거나 풍성하게 보이도록 꾸미지 않는다.
- 선택 직후 저장을 완료한 뒤 기존 중립 반응 두 종류만 보여준다. 하트·물음표·실패음·빨강/초록 평가색, 되돌리기는 금지한다. 에피소드 말의 기존 호감도 연출 시점은 유지한다.
- 이동 속도, 탐색량, 방문 순서, 퍼즐 성공, 장식 클릭, 사운드 켜기, 고백 대상에 숨은 성향 점수를 붙이지 않는다.
- 선택 후 주인공에 잔상을 남긴다면 모든 답에 동일한 방식만 허용한다. 성향·정답과 색을 대응시키지 않는다. 플레이 화면에 내부 축·성향치·호감도 숫자·금지 명칭을 노출하지 않는다.

## 6. 현재 근거와 제안 예산

`asset-metadata.json`의 삼각형 수는 저장된 제작 기록이며 이번에 Blender로 다시 계산한 값이 아니다. 아래 GLB bytes와 환경 텍스처 수는 현 파일을 읽어 확인했다. 고유 자산 합계는 중복 배치된 씬 렌더량이 아니다.

| 항목 | 현재 확인값·현행 상한 | 제안·측정 방법 |
| --- | --- | --- |
| 지형 | 기록 19,098 triangles, 파일 98,936 bytes, 재질 1. 생성기 상한 30,000 triangles / 1 MiB | 기존 상한 유지. 길 개선에 필요한 정점만 늘리고 전체 지형을 일괄 고밀도화하지 않는다. |
| 빵집 | 기록 1,864 triangles, 파일 25,060 bytes, 재질 2. 기존 상한 5,000 / 180 KiB | 시제품도 기존 상한 유지. 창·처마·진열 역할 단서에만 삼각형을 사용한다. |
| 나무·작은 꽃 | `tree-round` 492 triangles / 8,588 bytes / 재질 1, 노란 꽃 280 / 7,488 / 재질 1. 나무 상한 1,200 / 60 KiB, 꽃 300 / 20,000 bytes | 기존 자산별 상한 유지. 같은 크기의 꽃을 더 복잡하게 만들지 않는다. |
| 환경 고유 자산 | metadata 40종 합계 35,868 triangles / 369,624 bytes | 시제품의 고유 GLB 합계 증가 20% 이내를 임시 상한으로 제안. 현행 개별 상한과 함께 만족시킨다. 전 마을 확장 예산은 시제품 측정 후 확정한다. |
| 재질·텍스처 | 위 40개 GLB의 `images`·`textures` 합계 각각 0. AO PNG는 제작 자료다. 빵집 2재질, 예시 지형·나무·꽃은 각 1재질. 런타임 표식·접촉 그림자·FX 텍스처는 별도 | A 시제품에 새 환경 텍스처 0개, 자산별 재질 수 증가 0개. 두 재질 빵집을 이미 한 재질이라고 간주하지 않는다. 전체 런타임 재질·텍스처 메모리는 미측정이며 로딩 후 renderer 정보와 텍스처 크기·포맷을 기록한다. |
| 배치·드로 콜 | 월드 v2 `props` 537, `actors` 8, `paths` 51. 옛 문서의 `decor` 590·타일 271은 현행 수치가 아니다. 드로 콜·가시 triangles·GPU 시간은 미측정 | 대표 화면의 `renderer.info.render.calls/triangles`를 렌더 직후 전후 기록. 프레임당 드로 콜은 기준 화면 대비 +10% 이내를 임시 제안. 개체 수를 드로 콜로 환산하지 않는다. |
| 화면·그림자·FX | 모바일 DPR 상한 1.5, 그림자 맵 최대 1024, 방향광 1개. 꽃잎 12·반딧불 12, 호수 안개 2와 장소별 발광 존재 | 시제품은 이 상한을 유지하며 새 그림자 광원·후처리·상시 입자는 추가하지 않는다. 효과 축소가 FPS 개선을 보장한다고 쓰지 않는다. |
| 전체 배포 용량 | `check-size.mjs` 상한은 cinematics 제외 dist 10 MiB, cinematics 별도 13 MiB. 현재 빌드 산출물 합은 이번에 미측정 | 기존 상한 유지. 배포 빌드 후 `npm run check:size`로 각각 기록한다. 초기 다운로드·압축 전 자산 크기와 구분한다. |
| 과거 초기 로딩 | [11월 1일 보고](../reviews/perf-mobile-2026-11-01.md): FCP 1.84초, UI와 시작된 자산 요청 완료 6.47초, 완료 요청 전송 1.08 MiB, JS 힙 13.20 MiB | 당시 전송량은 현재 전체 자산 크기가 아니다. 최신 동일 조건 기준값을 다시 얻고 시제품 완료 요청 bytes 증가 +10% 이내를 임시 목표로 삼는다. 영상 포함/제외와 캐시 조건을 분리한다. |
| 프레임 목표 | 당시 이동 10초 평균 21.6 FPS는 Edge CDP·SwiftShader·CPU 4배 감속 결과. **실제 폰 FPS는 미측정** | 중급 Android Chrome·iPhone Safari에서 5분 예열 뒤 동일 동선 60초를 3회: 평균 30 FPS 이상, 프레임 간격 p95 50ms 이하를 최소 목표, 여유 기기는 60 FPS 지향. 기종·OS·브라우저·전원/발열·해상도를 기록한다. |

성능 미달 시 장식 중복·그림자 대상·FX를 줄이는 순서로 조정한다. 읽기 어려운 UI, 기대 답 암시, 충돌 무시로 프레임 목표를 맞추지 않는다. 예산은 성능을 보장하는 수치가 아니라 시제품을 멈춰 재검토할 기준이다.

## 7. 검수 절차와 확장 조건

1. **기준 고정:** 동일 커밋·저장 상태·카메라·시간 상태에서 빵집 접근→대화→이동의 전후를 남긴다. 원본 첨부 화면(1323×1148)은 비평 근거로 보존하고 서로 다른 종횡비를 픽셀 개선 증거로 비교하지 않는다.
2. **실제 화면 캡처:** 740×360·844×390 가로 두 크기, DPR 기록. 빵집 앞 무UI/일반 HUD/선택지 열린 상태, 광장, 도서관, 대장간, 호숫가, 기억의 문을 캡처한다. 390×844 세로에서는 회전 안내와 오입력 차단을 확인한다. 움직임 줄이기·무음 상태도 확인한다.
3. **10초 동작 영상:** 보행·급정지·방향 전환·대상 탭·막힌 경로·대화 종료·물건 운반과 내려놓기를 본다. 발 뜸·접촉 그림자·도구 관통·카메라 가림·탭 전달 문제를 기록한다. 재접속 뒤 작업물과 시간 상태가 맞는지도 확인한다.
4. **사람의 아트 판정:** 이름표를 가리고 빵집·주인공·갈 길을 물어본다. 관찰자 3명 중 2명이 5초 안에 각각 알아보고, 담당 검수자가 4절의 불합격 사례가 없다고 확인해야 한다. 이는 소규모 시제품 기준이며 통계적 UX 검증으로 보고하지 않는다. 최종 인상은 사용자가 고른다.
5. **계약·핵심 회귀:** asset 검사, 도달성 검사, 선택 저장 후 반응, 같은 문항 재선택 방지, 기존 ID·충돌·리그·클립·색공간을 확인한다. AO 보존 변경은 `demi.test.ts`의 기존 백색 덮기 기대값도 함께 바꾸고 공유 NPC 색 불변 회귀는 유지한다.
6. **구현 단계 필수 검사:** 루트에서 `node client/scripts/check-abraxas-assets.mjs`, `node scripts/check-village-reach.mjs`; client에서 `npm run typecheck`, `npm test`, `npm run build`, `npm run check:size`; server에서 `go vet ./...`, `go test ./...`, `govulncheck ./...`. 실행 실패·도구 부재는 결과에 명시한다. 이 문서 작성 단계의 실행 결과를 뜻하지 않는다.
7. **확장 문턱:** 수치·테스트가 통과해도 사람이 한 화면의 인상을 승인하기 전에는 다른 구역을 확대 제작하지 않는다. 변경 전후 성능·실제 캡처·남은 결함을 함께 보여준다. 제작 프리뷰만 있으면 아트 합격은 보류한다.

## 8. 작업 패키지와 독점 쓰기 순서
