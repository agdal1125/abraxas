# 행동으로 알아가는 꿈의 마을

2026-11-01 · T010 설계 제안 · 사람 검토 전 · 구현·콘텐츠·에셋 변경 없음

## 1. 요청 해석 요약

1. 마을의 꽃·나무·생활 소품을 살펴보며 짧은 발견을 쌓는다.
2. 심리 게임의 중심을 대사 연속 선택에서 운반·탐색·생활 문제 해결 중의 행동 선택으로 옮긴다.
3. 기존 측정 38문항과 별도 타이브레이커 4문항, 가중치·축·선택 순서·즉시 확정을 보존한다.
4. 파트너 선택은 닮음과 끌림을 돌아보는 계기로 만들며 새 측정으로 쓰지 않는다.
5. 원본 3D 디오라마·정사영·자유 이동을 유지하면서 파스텔·잔광·물결로 몽환적인 낮을 만든다.

근거 우선순위: [측정 정책](../../.agents/rules/game-design-policy.md) → [사람 요청 원문](../tasks/T010-user-brief-gameplay-dream.md) → 현행 데이터·구현 → 기존 설계. `village-3d-contract.md`·`design-system.md`의 KayKit·헥스 이동 지침은 `asset-control-overhaul.md`와 현행 Three.js/GLB·맵 v2로 대체되어 있다. 특정 작품을 따라 하라는 지시는 계승하지 않는다. 아래 값·문구·파일 형식은 승인 전 제안이다.

## 2. 물건 살펴보기

**대상:** 꽃 군집, 나무, 우물, 안내판, 연못 가장자리, 책더미, 빵 상자, 벤치, 가로등, 공구대. 기존 `flower-*`, `tree-*`, `well`, `book-stack` 등을 재사용한다. 안내판 모델은 현재 manifest에 없으므로 후속 아트의 신규 소품으로 등록한다. 연못은 물 한가운데가 아닌 걸을 수 있는 물가에 상호작용 지점을 둔다. 모든 잔풀에 표식을 붙이지 않고 대표 군집만 지정한다.

**입력:** 현재 `Village.onNearbyChange`·`interactNearby()`와 `Controls`의 버튼·Space/Enter 경로를 공유한다. NPC는 ‘말하기 / Talk’, 물건은 ‘살펴보기 / Examine’, 퀘스트 물건은 ‘들기 / Pick up’·‘놓기 / Put down’·‘전달하기 / Deliver’로 같은 버튼의 이름만 바꾼다. 근접 대상에 작은 테두리와 이름 하나를 표시하고, 대상 없음은 비활성화한다. 퀘스트의 느낌표와 감상용 표식은 모양으로 구별한다.

- `nearest()`의 현재 거리 0.85m·대상 유지 여유 0.1m를 기준으로, 접근 가능한 지점과 벽 가림을 재검증한다. 건물 중심·나무 수관·물속 좌표를 접근 지점으로 쓰지 않는다.
- 한 번에 한 대상만 포커스한다. 활성 퀘스트 목표와 감상 대상이 같은 자리면 퀘스트 동작을 먼저 제공하고, 완료 후 살펴보기를 복원한다. 두 측정 행동 사이에는 우선순위를 두지 않는다.
- 가까운 물건 탭도 같은 검증을 거친다. 이동·접촉·카메라 시선만으로 문구나 측정 선택을 실행하지 않는다. 대사창을 열면 이동을 멈추고, 닫은 입력이 다음 행동까지 실행되지 않게 한다.
- 반복 감상은 허용한다. 살펴본 횟수·순서·체류 시간은 성향·호감도·가치·초대권에 영향을 주지 않는다. 현재 측정 문항에 쓰이는 소품의 일반 감상은 선택 힌트를 주지 않도록 해당 단계에서 숨긴다.

**데이터 제안:** 배치별 식별자는 이미 있는 `props[].id`를 보존하고 `examineKey`와 접근 지점 `interactAt: {x,z}`만 필요한 배치에 추가한다. 물가 등 모델 없는 지점은 `village.json`의 별도 `interactions`에 `id`, `examineKey`, `x`, `z`를 둔다. manifest는 모델·충돌 계약만 담당한다. 언어 파일은 동일 키의 `content/i18n/ko/examine.json`, `content/i18n/en/examine.json`으로 나눈다.

```json
{
  "flower.pink": { "name": "분홍 꽃", "text": "꽃잎에 작은 꿈이 내려앉았다." },
  "well.plaza": { "name": "우물", "text": "물 아래에도 하늘이 있다." }
}
```

`name`은 근접 안내·접근성 이름, `text`는 한두 줄 감상이다. 선택지·점수 필드는 없다. EN도 같은 구조를 쓰며 `translations()`에 명시적으로 연결한다(현재는 `ui`·`items`만 반환). 빌드 시 KO/EN 키 일치를 검사하고 누락 문구에 내부 키를 표시하지 않는다. 버튼은 최소 48px, 글자 확대·키보드 포커스를 유지한다.

| 대상 | KO 톤 예시 | EN 톤 예시 |
| --- | --- | --- |
| 꽃 | 꽃잎에 작은 꿈이 내려앉았다. | A little dream rests on the petals. |
| 나무 | 잎 사이로 느린 바람이 잠든다. | A slow breeze sleeps among the leaves. |

| 책더미 | 책장 사이에 오후가 끼어 있다. | An afternoon rests between the pages. |

## 3. 행동형 퀘스트

### 구조와 확정 시점

운반(집기→이동→전달), 길 찾기(경로·탐색 방식 선택), 생활 문제 해결(배치·분배·보강), 퀴즈/라이트 퍼즐(표식 대조·순서 맞추기·연결)을 작은 단계로 조합한다. 기존 에피소드당 4.5분 안에서 대사 일부를 행동으로 치환한다. 퍼즐은 기본 30~60초, 힌트 무제한·실패 종료 없음·자동 완성 허용을 권고하며 시간 제한은 없다. 난이도는 §7에서 결정한다.

상태 흐름: `locked → available → active → ready_to_report → completed`. `active` 안에서 `stepId`로 목표를 진행하고, 측정 행동만 `awaiting_choice → committing → committed → acting → step_done`을 지난다. 비측정 행동은 저장된 진행 단계만 갱신한다. NPC에게 돌아가야 하는 마지막 보고와 모든 필수 행동이 끝나기 전에는 에피소드를 완료하지 않는다.

- **의도 확정:** 행동 지점에서 두 행동의 의미를 기존 문구로 함께 제시하고 a 다음 b 순서를 유지한다. 선택 버튼을 누르는 순간 해당 `{id,pick}`를 확정한다. 이후 실제로 물건을 들고 걷고 배치한다. 바닥 영역에 먼저 발을 들였다고 자동 측정하지 않는다. 감상·회상 문항도 의미를 말로 밝히고 소품 동작을 이어 붙인다.
- **즉시 저장:** 선택 입력을 잠그고 로컬에 변경 불가 대기 기록을 남긴 뒤, 서버가 같은 `playId`·문항 ID의 최초 선택을 확정한다. 서버 확인과 로컬 확정 기록이 끝난 후에만 행동 결과·NPC 반응을 보여준다. 실패하면 같은 선택 재전송만 제공하며 다른 선택으로 바꿀 수 없다. 새로고침·다중 탭·응답 유실 시 서버의 확정 기록으로 복구한다. 서버는 인증·현재 구간·다음 문항·중복을 검증하고 최종 결과를 다시 계산한다.
- **현재의 결손:** `Game.choose()`는 로컬 저장만 호출하고 저장 실패도 무시한다. 서버 연동을 기존 기능처럼 간주하지 않는다. 이 조건이 구현되지 않으면 행동 측정을 출시 완료로 보지 않는다. 살펴보기는 독립적으로 구현할 수 있다.
- **재개:** `questId`, `stepId`, `carriedItemId`, 배치 상태를 측정 로그와 분리한다. 선택 저장 뒤 행동 도중 종료해도 같은 선택의 미완료 행동부터 복구한다. 완료 보상·전달은 중복 적용하지 않는다. 기존 `abraxas-prototype` 로그는 삭제하지 않고, 답변한 문항을 다시 묻지 않는 복구 단계를 마련한다.
- **운반:** 한 번에 한 물건만 든다. 손에 든 작은 모델과 ‘들고 있음’ 표시를 제공한다. 지정 선반·목표 자리에서만 놓을 수 있고, 중간에 놓아도 그 자리에 다시 집을 수 있다. 잘못된 대상에는 짧은 안내만 주며 물건을 소모하지 않는다. 줍기·놓기·걸음 속도·실수·힌트 사용·퍼즐 정오답은 측정하지 않는다.
- **진행:** ‘빵을 공방에 전하기 → 진열하기 → 모카에게 돌아가기’처럼 현재 목표 한 줄과 끝난 단계의 체크만 표시한다. 미니맵·범용 인벤토리·물리 운반·채점 퀴즈는 추가하지 않는다. 두 분기의 터치 수·이동 부담·힌트 접근성을 비슷하게 맞추고 어느 쪽에도 추가 보상이나 실패 확률을 붙이지 않는다.

`content/quests/episodes.json`(신규 제안)에 단계·대상 ID·`itemId`·`a/b → actionId`·다음 단계를 두고, 안내 문구는 `content/i18n/<lang>/quests.json`에 둔다. 가중치·NPC 기대 답변은 복사하지 않고 `items.json`만 참조한다. ink와 일반 문항이 같은 ID를 중복 실행하지 않도록 단일 확정 경로를 쓴다. 현재 `episodeStage(answered)`만으로는 행동 완료를 알 수 없으므로 문항 수 기준에 퀘스트 완료 조건을 함께 적용해야 한다.

### 기존 38문항의 행동 매핑

아래는 데이터의 나열 순서다. 실제 플레이에서는 **에피소드 자유 순서**, 에피소드 안 `01→06`, 완료 횟수에 따른 막간 `1→2→3`, 축제 `01→05`를 보존한다. 기존 `id/segment/kind/axis/npc/picks/weights/values`는 변경하지 않는다. 현재 38개는 주 적재 ±12·보조 적재 없음이며, 축별 역균형도 그대로다. 행동 표현이 의미를 바꾸는 경우 해당 행의 구현을 보류하고 사람 승인을 받는다.

**해석 주의:** `moka_06`, `echo_05`, `interlude_3_01`, `festival_05`는 몸짓만으로 판단 기준·내적 생각을 알 수 없다. 원문 의도를 담은 두 문구를 먼저 고른 후 몸짓·회상 연출을 붙인다. 이를 ‘물건 위치를 고르면 속마음을 추정’하는 문항으로 바꾸지 않는다. `or_02`의 혼자/수소문은 선택이지만, 퍼즐 힌트 버튼은 별개로 누구나 쓸 수 있다. `interlude_2_02`는 선택 전 원문의 위험·보상 맥락을 유지하되 실제 열쇠 유실·추가 성향 보상은 없고, 두 분기 모두 다음 문항으로 간다.

NPC 기대 답변이 없는 14문항(프롤로그 3·막간 6·축제 5)은 `npc:null`을 유지한다. 퀘스트 NPC가 안내해도 해당 에피소드 6문항의 측정 상대는 원래 공략 캐릭터다. 선택 전 NPC 선호·추천·웃는 표정·특별한 색·빛으로 분기를 유도하지 않는다. 선택 후 공감/생각 반응은 동등하게 연출하며 하트는 에피소드 종료 때만 모아 보여준다. 기존 심부름 완료·공동 이벤트 보상 정책은 유지하되 문항·퍼즐·소품마다 보상을 새로 붙이지 않는다.

보상 연결안: 담당 심부름의 모든 필수 전달·보고를 끝내면 해당 공략 캐릭터에게 정책의 +8을 한 번 적용한다. 공동 이벤트 편들기는 5개 축제 측정 문항과 별개의 ‘함께 일할 사람’ 선택으로 분리하고, 선택한 한 사람에게 정책의 +10을 한 번 적용하는 안을 제안한다. 그 장면의 시점은 §7의 사람 결정 전까지 미확정이다. 둘 다 서버가 완료 사건을 검증하고 같은 회차·사건에는 중복 지급하지 않는다. 현행 `score()`에는 이 두 보상과 고백 판정이 없으므로, 기존 문항 계산을 보존한 채 별도 비측정 사건으로 합산해야 한다. 장면·횟수 확정과 구현 검증은 고백/결과 완료의 선행 조건이다.

## 4. 자기 성찰로서의 파트너 선택

흐름은 **기억의 문 → 잠깐 멈춤 → 상대 선택 → 고백 반응 → 결과 3장**이다. 현행 `nextSegment()`는 문에서 곧바로 결과로 가므로 고백 단계는 후속 신규 구현이다. 원래 고백 성공 기준은 유지하고 실패가 ‘나쁜 성격’처럼 보이지 않게 응답의 길이·화면 품질을 동등하게 한다.

1. ‘함께 있고 싶은 마음은 어디에서 왔을까. 닮아서 편안했을까, 달라서 눈길이 갔을까.’라는 짧은 혼잣말을 둔다. EN 예: “What drew you closer: a familiar feeling, or something different?”
2. 네 사람을 동일 크기·밝기로 보여주고 함께했던 일의 중립적인 장면 한 컷씩 제공한다. 호감도 순위·성공 예측·추천 상대를 표시하지 않는다.
3. 상대를 고르고 ‘이 마음을 전하기’로 고백한다. 닮음/끌림은 두 이유가 겹칠 수 있다고 안내한다. 이유를 직접 고를지는 §7 결정 전까지 필수 입력으로 만들지 않는다.
4. 선택한 상대 ID는 진행 기록으로만 저장한다. 고백 대상·이유·선택 시간은 측정 로그·가치 태그·호감도 증가·초대권 조건에 넣지 않는다. 고백을 성향 문항으로 늘리지 않는다.

**‘그 사람’ 카드:** 서버가 확정한 플레이어 결과와 선택 상대의 **이번 플레이 최종 성향**을 기존 규칙으로 비교해 일상 문장만 만든다. 공통점·차이를 각각 최대 한 문장, 마지막에 열린 질문 한 문장을 둔다. 동일 항목이 없거나 차이가 없으면 억지로 만들어 넣지 않는다. 비교할 항목은 고정된 순서에서 고르며 숨은 점수의 크기나 ‘궁합’으로 순위를 매기지 않는다. 상대에게 플레이어용 타이브레이커를 추가하지 않는다.

- 공통점 예: ‘둘 다 익숙한 것을 소중히 간직했어요.’
- 차이 예: ‘당신은 마음을 먼저 살폈고, 그 사람은 기준을 먼저 짚었어요.’
- 성찰 예: ‘편안했던 건 닮은 점이었나요, 더 알고 싶어진 건 다른 점이었나요?’

‘좋은 짝’, ‘상대도 나를 좋아함’으로 해석하지 않는다. 나/그 사람/마을 3장과 기존 심리 게임 고지·처음의 나 보관을 유지한다. 수치·코드·축 이름·금지 명칭은 화면에 쓰지 않는다. 월드의 `A~D`, `s1j2` 등은 연결용 ID로만 쓰고, 화면은 루미·모카·에코·오르 및 역할 이름(무대지기·시식 안내인·책 정리인·공방 조수)을 사용한다.

## 5. 몽환적 아트 디렉션

방향은 **낮의 생활감이 남은 꿈**이다. 둥근 원본 형태·3등신·실루엣·고정 정사영을 유지한다. 환경을 먼저 부드럽게 하고 인물과 길의 구분을 남기는 안을 권고한다. 전면 저채도화는 캐릭터 구분을 약하게 만들 수 있으므로 §7에서 강도를 결정한다. 아래 색은 제작 출발점이며 승인된 토큰이 아니다.

| 영역 | 현재 → 제안 |
| --- | --- |
| 하늘·바다 | 선명 파랑 `#5BC0F8` → 안개 라벤더 `#DDD8F1` / 물 민트 `#A9D8D3` |
| 풀·길 | 풀 `#5CC96B`, 길 `#F2B35E` → 풀 `#B5D9C4`, 길 `#EBD3B9` |
| 꽃·지붕 | 강한 분홍·코럴 → 꽃 `#E8BDD4`, 지붕 복숭아 `#E7B6AB` |
| 인물 대표색 | 코럴·주황·보라·청록 계열 유지 → 각각 `#E99D8C`·`#E9BE79`·`#B39AD9`·`#7DBDB2` 시험 |
| UI | 종이 `#FFF8EC`, 글자 `#3B2A22` 유지. 테두리 `#D8CBE6`, 강조는 인물보다 약간 선명하게 |

- **하늘·안개·원경:** 정사영 상부 시점에 억지 수평선을 넣지 않는다. 섬 바깥 바다와 배경을 같은 계열로 잇고 화면 가장자리의 흐린 구름층·먼 섬 실루엣으로 깊이를 준다. 지면 가까이에는 얕은 거리 안개만 제안한다. 통행 경계·발밑·목표는 선명하게 남긴다. 체적 안개·카메라 회전·원근 전환은 제외한다.
- **빛·입자:** 반딧불은 물가·나무 그늘, 떠다니는 꽃잎은 꽃밭 근처에만 둔다. 특정 선택지로 흘러가거나 정답을 가리키지 않는다. 최초 제작 예산은 화면 내 이동 입자 합계 24개·주요 잔광 8개 이내, 공유 소형 아틀라스 하나다. 이는 상한 제안이며 실기기 측정으로 더 줄인다. 움직임 줄이기에서는 입자를 멈추거나 숨긴다.
- **글로우:** 블룸 대신 가로등·반딧불·문 가장자리의 작은 가짜 글로우 스프라이트를 권고한다. 화면 전체를 덮는 반투명 레이어, 입자별 실제 광원, 후처리 블룸·DOF는 쓰지 않는다. 투명 겹침 면적과 드로 콜도 예산에 포함한다.
- **물·연못:** 기존 물 경계에 맞춘 민트색 면, 느린 잔물결 무늬, 물꽃 옆 작은 반짝임으로 표현한다. 실시간 반사·굴절·물리 파도는 제외한다. 물가와 다리의 통행 구분은 안개·반짝임이 가리지 않는다.
- **재색칠 범위:** agy가 환경의 지형·수관·지붕·생활 소품 `COLOR_0`를 먼저 수정하고 해당 GLB를 Blender에서 다시 내보낸다. 인물은 대표색을 낮추는 안이 선택되면 의상·소품 중심으로 재내보내되 얼굴·실루엣·리그·클립은 유지한다. 전체 메시를 새로 모델링할 필요는 없다. 새 안내판·운반 소품 등 빠진 형태만 추가 제작한다.
- **색 관리 선행:** 현행 환경 로더에는 버텍스 컬러 역변환 보정이 있고, lessons에는 원본의 이중 선형화 문제가 기록되어 있다. 파스텔화를 색 오류 보정으로 대신하지 않는다. agy의 원본 색공간 수정과 Terra의 런타임 보정 제거는 같은 통합 단계에서 비교 칩·실제 화면으로 확인한다.
- **UI:** 크림색 낮은 대사창, 부드러운 라벤더 테두리, 진한 본문을 유지한다. 반투명 유리 UI로 읽기 어렵게 만들지 않는다. 파스텔 이름표에는 진한 글자를 사용하고 본문 대비 4.5:1 이상·48px 터치 영역·글자 확대를 검수한다. 두 측정 선택지의 색·모양·빛·등장 속도는 같다.

기존 목표(초기 요청 10MiB 이하, 모바일 DPR 1.5 이하, 주 패스 80/그림자 포함 120 드로 콜 이하, 저사양 실기기 p95 프레임 시간 33.3ms 이하)를 넘지 않는 선에서 효과를 추가한다. 목표는 아직 이 설계의 실측 결과가 아니다. 부족하면 입자·잔광·그림자부터 줄이고 텍스트·목표 가독성을 보존한다.

## 6. 작업 분할·의존 순서·완료 기준

## 7. 사람에게 물을 질문 목록

측정 수치·문항 순서 변경은 이 안에 필요하지 않으므로 승인 요청에 올리지 않는다. 행동만으로 드러내기 어려운 감상은 원문 선택을 유지한다. 아래 네 결정만 Claude를 통해 사람에게 확인한다.

1. **고백에서 닮음/끌림의 이유를 직접 고르게 할까요?** ① 성찰 문구만 보여주기 ② 선택 후 ‘닮아서 편안해요 / 달라서 끌려요 / 둘 다예요 / 아직 모르겠어요’ 중 선택하기. **권고: ①.** 첫 버전의 흐름을 짧게 유지하며 결과 카드에서 스스로 돌아보게 한다. ②도 새 측정이나 궁합 판정에는 쓰지 않는다.
2. **몽환적 색감은 어디까지 적용할까요?** ① 환경은 파스텔, 인물 대표색은 식별 가능하게 유지 ② 인물까지 파스텔로 통일 ③ 현재 선명한 색을 유지하고 빛·안개만 추가. **권고: ①.** 꿈같은 배경과 인물·목표의 가독성을 함께 확보한다.
3. **주요 퀴즈·퍼즐의 생각할 시간은 어느 정도가 좋을까요?** ① 30~60초의 관찰·짝 맞추기 ② 1~2분의 간단한 순서 추론. **권고: ①.** 약 31분 안에서 행동 선택을 중심에 둔다. 어느 안이든 제한 시간·실패 종료 없이 힌트와 자동 완성을 제공하고 정오답은 측정하지 않는다.
4. **공동 이벤트 편들기 보상을 어떤 비측정 장면에 연결할까요?** ① 축제 5문항 뒤 ‘같이 마무리할 사람’ 한 명 선택 ② 축제 시작 전 ‘함께 준비할 사람’ 한 명 선택. **권고: ①.** 측정 직전 특정인에게 잘 보이려는 동기를 덜 만들 수 있다. 두 안 모두 회차당 한 사건·한 대상에게 기존 +10만 적용하는 제안이며, 장면·횟수는 사람 승인 후 확정한다. 승인 전에는 고백 판정에 임의 반영하지 않는다.
