## 1. 어떤 문장이 어떤 선택에 붙는가

`client/src/ui/game.ts:518,523`과 `client/src/core/scoring/index.ts`의 `npcMatches`를 읽고 정리했다.

- NPC가 없는 문항(프롤로그, 막간, 축제, 기억의 문 18개)은 항상 `thinking`만 보인다. `empathy` 18문장은 지금 화면에 나오지 않는다. 축제 4문항은 화자가 NPC여도 `npc: null`이라 같다.
- NPC 문항은 NPC 현재값의 부호가 기대 극이다. 시작값이 ±30이고 한 번에 20씩 움직이므로 같은 NPC·같은 축의 **첫째와 둘째 문항은 짝이 고정**된다. NPC 극을 고르면 공감, 반대 극을 고르면 생각에 잠김이다. **셋째 문항**(lumi_05·06, moka_05·06, echo_05·06, or_05·06)은 앞의 두 문항에서 모두 NPC 반대 극을 골랐을 때만 짝이 뒤집힌다.
- 그래서 판정은 두 단계로 했다. 고정 짝에서 실제로 보이는 조합이 틀리게 읽히는지 먼저 보고, 그다음 반대 조합으로도 자연스러운지 본다. 셋째 문항은 두 조합이 모두 실제로 나온다.

## 4. 누가 결정하는가

### 메인이 바로 적용해도 되는 것

- 결함 7건의 반응 문장 교체(ko·en), 개선 4건(lumi_01, lumi_04, interlude_1_02, echo_03 en).
- 이유: 반응 문장은 성향 수치, 문항 수, 선택지 문구가 아니다. 어느 반응이 나오는지 정하는 로직도 그대로다. 정책 오염 방지 2항("좋고 나쁨이 없는 두 종류")과 4항·5항을 지키기 위한 복구라서 측정 의미를 바꾸지 않는다.
- 적용 뒤 `npm run check:scoring`, `node client/scripts/check-dialogue.mjs`, 클라이언트 `npm run typecheck && npm test`.

### 사람 확인이 필요한 것

1. **직전 대사 5건.** 정책 5항 위반 해소라 메인 적용이 가능해 보이지만, M0 보고서는 moka_01 직전 대사 삭제를 "전부 사람 승인 필요" 묶음에 넣었다. 같은 기준을 적용할지 사람이 정해 준다.
2. **moka_06.** 반응 교체만으로는 부족하다. M0 보고서에서 사람 결정으로 남긴 "문구만 고칠지, 모카가 아닌 장면으로 옮길지"에 따라 반응도 다시 써야 한다. 제안 문구는 문항을 그대로 둘 때의 안이다.
3. **구조 문제: 반응의 종류 자체가 NPC의 극을 가르친다.** 문장을 모두 중립으로 고쳐도 남는다.
   - 같은 NPC·축의 첫째와 둘째 문항은 짝이 고정이라, 플레이어가 공감을 받은 선택이 곧 그 NPC의 극이다. 예를 들어 moka_01에서 완만한 길을 골라 공감("응, 그 길로…")을 받으면 모카가 신중 쪽을 반긴다는 걸 알게 되고, 호감을 얻고 싶은 사람은 moka_03·05에서 그쪽을 고를 수 있다.
   - 형식 차이도 일정하다. 24개 NPC 문항의 공감은 모두 "응/좋아/그래"로 시작하는 동의이고, 생각에 잠김은 거의 모두 "아/오/와 … 궁금해/일까"로 끝나는 물음이다. 몇 문항만 보면 플레이어가 이 규칙을 배운다. 오르의 공감에는 인물 설정표상 칭찬어인 "좋아."가 들어 있다.
   - 이건 기획(기대 일치 시스템)에서 나오는 문제라 문장 수정으로 풀 수 없다. 선택지는 두 가지다. (가) 두 반응의 형식을 맞춘다: 둘 다 짧은 수긍 뒤에 내용을 붙이고, 차이는 내용에만 둔다(예: 공감 "응, 그렇게 하자. 빵이 좋아하겠다." / 생각에 잠김 "응, 그렇게 하자. 어떻게 될지 궁금하네."). (나) 현행을 유지하고 플레이 데이터에서 NPC별 둘째·셋째 문항의 NPC 극 선택 비율이 첫째보다 오르는지 본다. (가)는 공감과 생각에 잠김을 구분해 둔 정책 2항의 취지를 약하게 만들 수 있어 사람 결정이 필요하다.
4. **미노출 공감 18문장.** 지금은 화면에 나오지 않는다. 그중 prologue_03("마음 가는 대로"), festival_03("따뜻한"), gate_b("소중하게 생각해도 좋아")는 한쪽 극으로 기운다. 나중에 코드가 NPC 없는 문항에도 공감을 보여 주게 바뀌면 바로 결함이 된다. 지금 고칠지, 쓰지 않는 문장으로 표시할지 정해 준다.

## 5. 재검 조건

- 문장을 바꾼 뒤 위의 기계 검사를 통과한다.
- 문장 수정이 반영된 빌드로 소규모 플레이를 해서 다음을 본다. 제안 기준이며 수치는 사람이 정한다(경험칙, 근거 등급 D).
  - NPC별로 첫째 문항 대비 둘째·셋째 문항의 NPC 극 선택 비율. 크게 오르면 4절 3번(구조 문제)의 신호다.
  - moka_02, moka_06의 선택 비율. 한쪽 70% 초과면 재수정 신호(M0 보고서와 같은 기준).
- 엔지니어 제안(코드는 고치지 않았다): 반응 문장에 선택지의 2음절 이상 명사가 그대로 들어가는지, 극 단어 목록(마음·사실·새로·익숙·도전·신중·안전·전통 등)이 들어가는지 잡는 검사를 `check-dialogue`에 넣으면 이번 같은 뒤바뀜을 다시 잡을 수 있다. 의미까지는 못 잡으니 사람의 읽기를 대신하지 않는다.

## 6. 근거 등급

- 문장 판정과 제안 문구는 모두 D(문구 분석과 추론)다. 플레이 데이터는 M0에서 moka_02 뒤바뀜을 확인한 것뿐이고 선택 비율 데이터는 없다(데이터 n= 없음).
- 반응 짝 고정 분석은 코드를 읽어서 확인한 사실이다(`client/src/core/scoring/index.ts:11-27,46-55`, `client/src/ui/game.ts:510-523`, `content/scoring/npcs.json`, `content/scoring/rules.json`). 심리학 주장이 아니므로 등급을 붙이지 않는다.
- 피드백이 뒤 문항 응답을 바꾼다는 주장(4절 3번)은 일반적인 강화 학습과 사회적 바람직성 논리에 기댄 추론이다. 이번에 논문을 읽지 않았으므로 문헌을 인용하지 않는다. 등급 D.

## 7. 외부 전문가에게 물을 질문

1. 선택 직후 상대의 반응 종류(동의 대 궁금해함)가 일관되게 다를 때, 같은 상대가 뒤에 묻는 강제선택 문항에서 응답이 상대 쪽으로 쏠리는 정도를 재는 표준 방법이 있는가. 첫 문항 대비 뒤 문항의 선택 비율 비교로 충분한가.
2. 반응을 "둘 다 수긍하되 내용만 다르게" 맞추는 것과 "반응을 아예 하나로 통일"하는 것 중 어느 쪽이 측정 오염을 더 줄이는가. 재미 게임에서 반응의 차이가 주는 몰입과 오염 사이의 기준이 있는가.
3. 혼잣말 반응(플레이어 화자)도 응답 뒤의 자기 확인 효과로 뒤 문항에 영향을 주는가. 혼잣말은 중립 문장 하나로 충분한가.
