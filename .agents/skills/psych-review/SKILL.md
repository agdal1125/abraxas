# 심리 검토

`design-review`는 정책과 데이터 형식을 본다. 이 스킬은 문구가 실제로 무엇을 재고 무엇을 약속하는지 본다.

## 1. 기계 검사

```bash
npm run check:scoring
node client/scripts/check-dialogue.mjs
```

오류가 있으면 멈추고 보고한다. 측정 수치는 고치지 않는다. `check:scoring`은 무작위 선택 시뮬레이션이라 바람직성을 잡지 못한다.

## 2. 문항 점검

`items.json`만 보지 않는다. 플레이어가 실제로 보는 맥락을 함께 읽는다: `content/ink/ko/`의 앞뒤 대사, `content/i18n/ko/dialogue.json`의 반응, 퀘스트 흐름, `content/i18n/en/`의 같은 문항.

| 코드 | 질문 |
| --- | --- |
| P1 바람직성 | 한쪽이 더 착하거나 똑똑하거나 멋져 보이는가. 한쪽이 눈앞의 NPC 마음에 들 것 같은가 |
| P2 구성 개념 | 이 선택이 재려는 축을 실제로 가르는가. 다른 축이나 호감 전략이 더 크게 갈리는가 |
| P3 맥락 의존 | 성격보다 상황 정보가 답을 정하는가. 인물 설정을 알수록 기대 답을 맞히기 쉬운가 |
| P4 학습 | 앞 장면의 반응이나 연출이 뒤 문항의 정답을 가르치는가. 반응이 고른 선택과 맞게 붙는가 |
| P5 공정성 | 나이, 성별, 몸 상태, 문화, 경제 사정으로 뜻이 달라지는가 |

문항마다 `문제 없음` 또는 코드, 심각도(높음, 중간, 경미), 인용을 쓴다. 나쁜 문항이 없으면 없다고 쓴다. 높음이 하나라도 있으면 `수정 필요`, 문구나 수치 변경이 따르면 `사람 결정 필요`도 함께 쓴다.

## 3. 결과 문구 점검

| 코드 | 질문 |
| --- | --- |
| R1 Barnum | 반대 유형이 읽어도 맞는 말인가. 그렇다면 고친다 |
| R2 근거 | 실제 선택에 이어지는가 |
| R3 낙인 | 사람을 재단하거나 고칠 대상으로 말하는가. 유형의 우열을 암시하는가 |
| R4 이분법 | 경계 축을 확정된 사실처럼 말하는가 |
| R5 효과 주장 | 진단, 치료, 성격 변화, 관계 예측을 약속하는가 |
| R6 노출 | 축 이름, 수치, 내부 코드, 'MBTI'가 있는가 |
| R7 쓸모 | 읽은 뒤 실제로 해 볼 수 있는 행동이 있는가 |

## 4. 근거 등급

주장마다 등급을 붙인다.

- A: 메타분석이나 사전등록 재현, 원문 확인
- B: 개별 실험, 원문 또는 초록 확인
- C: 이론 수준, 2차 자료
- D: 경험칙이나 추론. 그렇게 표시한다

문구 분석은 D다. 선택 비율 같은 플레이 데이터가 있으면 D 옆에 `데이터 n=`으로 적는다. 플레이어 화면에 효과 주장을 넣거나 효과를 근거로 제안할 때만 문헌을 찾는다. 그때는 A나 B가 필요하고, 그래도 재미 게임의 범위로 낮춰 말한다. 기억으로 인용하지 않는다. 찾지 못했으면 찾지 못했다고 쓴다.

## 5. 윤리

- 공유 보상, 광고, 재플레이 유도에 압박이나 부끄러움을 이용하는 문구가 있는지 본다. 설치돼 있으면 `dark-pattern-check`를 쓴다. 법률 판단은 하지 않는다.
- 미성년자를 포함한 일반 이용자를 가정한다. 연애 결과가 상처가 되지 않는지 본다.
- 민감한 결과 저장과 공유 범위를 확인한다. 어떤 선택을 했는지 동의 없이 남에게 보이면 안 된다.

## 6. 결과 형식

판정, 항목별 표, 수정 제안(현재 문구와 제안 문구), 근거 등급, 외부 전문가에게 물을 질문, 사람 결정이 필요한 항목을 쓴다. 재검 조건을 적는다.
