# 기능 QA

재미와 측정 타당성은 보지 않는다. 동작하는지, 막히지 않는지, 서버가 잘못된 요청을 거절하는지 본다.

## 1. 범위 정하기

`git diff main...HEAD --stat`과 브리프를 보고 아래에서 해당하는 행을 고른다. 고른 행과 고르지 않은 이유를 보고서 첫머리에 쓴다.

| 바뀐 것 | 꼭 볼 것 |
| --- | --- |
| 흐름, 에피소드, 심부름, 퍼즐 | 해당 구간 끝까지 진행, 재개, 연타 |
| `server/`, 명령 API, 저장 | 신뢰 경계, 재개, 에뮬레이터 E2E |
| UI, HUD, 대사창, 결과·공유 화면 | 화면 크기 × 글자 크기, 입력 방식, 언어 |
| 렌더, 카메라, 이동, 충돌 | 갇힘, 화면 밖 목표, 회전 |
| 대사·문구 | 노출 금지 검사, 언어 전환, 줄 넘침 |
| 버그 수정 PR | 원래 재현 단계, 바로 옆 경로 |

## 2. 자동 검사

먼저 돌린다. 실패하면 탐색 시험보다 이것을 먼저 보고한다.

```bash
npm --prefix client run typecheck
npm --prefix client test
npm run check:scoring
node client/scripts/check-visible-names.mjs
node client/scripts/check-dialogue.mjs
```

흐름이나 서버가 바뀌었으면 E2E 세 시나리오를 돌린다. 출력 폴더를 시나리오별로 나눈다.

```bash
node scripts/e2e-play.mjs ko .e2e/qa-ko-a a-auto
node scripts/e2e-play.mjs ko .e2e/qa-ko-b b-manual
node scripts/e2e-play.mjs ko .e2e/qa-ko-resume resume
```

영어 문구나 UI가 바뀌었으면 `en`으로도 돌린다. `server/internal/store`나 인증이 바뀌었으면 `--emulators`를 붙인다. 각 `run-summary.json`의 `reached`, `errors`, 비정상 응답 수를 표에 옮긴다. E2E가 이미 보는 것(네 화면 크기 × 글자 17·20px의 보드 넘침, 48px 버튼, 재개 지점, 터치·마우스)은 탐색 시험에서 다시 하지 않는다.

## 3. 탐색 시험

`node scripts/dev-play.mjs <vite포트> <api포트>`로 띄우고 내장 브라우저로 한다. 범위에 든 행만 한다.

- **진행 막힘**: 목표가 화면 밖일 때, 대화 중 이동 입력, 퍼즐을 틀리게 놓고 되돌리기, 같은 NPC에 두 번 말 걸기.
- **연타와 순서**: 선택지·다음·보고 버튼 연타, 저장 응답이 오기 전 다른 버튼 누르기. 선택이 두 번 저장되거나 반응이 저장 확정 전에 나오면 결함이다.
- **재개**: 구간 중간에 새로고침, 탭 닫고 다시 열기, 저장 요청 중 새로고침. 새 회차가 생기거나 진행이 되돌아가면 결함이다.
- **환경 변화**: 세로↔가로 회전, 백그라운드에 뒀다가 돌아오기, 전체 화면 들어가고 나오기, 뒤로 가기.
- **네트워크**: API 서버를 멈춘 상태에서 선택하기, 다시 켠 뒤 이어지는지. 오류 문구가 플레이어 말로 나오는지.
- **언어**: ko↔en 전환 뒤 대사, 버튼, 결과 카드에 다른 언어나 키 이름이 섞이는지.
- **노출 금지**: 화면, 공유 문구, 페이지 제목에 축 코드, 성향 수치, 호감도 숫자, 'MBTI'가 보이는지.

## 4. 신뢰 경계

로컬 서버에만 한다. `dev-play`는 가짜 인증을 쓰므로 브라우저 콘솔의 `fetch`나 Node 스크립트로 `/v1/plays/{playId}/commands`에 직접 보낼 수 있다. 서버가 거절하거나 무시해야 하는 것:

- 이미 답한 문항에 다시 답하기, 없는 문항·선택 값
- 순서를 건너뛴 명령(에피소드를 마치기 전 결과 요청 등)
- 다른 회차 ID, 다른 사용자 토큰
- 클라이언트가 계산한 유형·호감도·초대권 값을 실은 요청
- 본문 크기 초과, 잘못된 JSON

받아들여지면 S1이다. 응답 코드와 본문, 이후 `GET /v1/plays/{playId}` 상태를 증거로 남긴다.

## 5. 심각도

| 등급 | 뜻 |
| --- | --- |
| S1 | 진행 불가, 저장 손실·오염, 신뢰 경계 뚫림, 측정 결과가 조작과 다르게 기록됨 |
| S2 | 주요 기능 오동작, 우회는 있음 |
| S3 | 화면 깨짐, 줄 넘침, 잘못된 문구, 특정 조합에서만 나는 어색함 |
| S4 | 사소함 |

## 6. 보고서 양식

`docs/qa/YYYY-MM-DD-<대상>.md`:

```markdown
대상: <PR 또는 브랜치> / 커밋 <해시> / <날짜>
범위: <고른 행>, 제외: <행과 이유>

## 자동 검사
명령 | 결과(통과/실패/미실행) | 증거

## 조합
조합(화면, 글자, 입력, 언어, 서버 모드) | 결과(통과/실패/미확인)

## 결함
### QA-<번호> <한 줄 요약> (S1~S4, 재현 n/m)
- 환경: 커밋, 화면, 입력, 언어, 서버 모드
- 단계: 1. … 2. …
- 기대 / 실제
- 증거: 스크린샷 경로, run-summary, 콘솔·응답
- 훅 없이 재현: 예 / 아니오
- 의심 위치(추정): 파일:줄

## 재현 실패
제보 | 시도한 조건

## 사람이 정할 것
```

스크린샷과 E2E 출력은 `.e2e/`(git 제외)에 두고 보고서에는 경로만 쓴다. 저장소에 남길 그림이 꼭 필요하면 `docs/qa/img/`에 작게 넣는다.

## 7. 회귀 확인

수정 PR이 오면 결함의 '단계'를 처음부터 그대로 따라 한다. 그다음 같은 구간의 다른 NPC나 다른 선택으로 한 번 더 한다. 결과를 원래 보고서의 결함 아래에 `회귀 확인: <PR> 통과/실패`로 덧붙인다.

## 메인을 위한 안내

- QA 보고의 S1·S2는 병합 전에 처리하거나 사람에게 보류를 묻는다.
- 같은 결함이 critic 보고에도 있으면 같은 것으로 묶는다.
- 고친 사람이 아닌 QA가 회귀를 확인한다.
