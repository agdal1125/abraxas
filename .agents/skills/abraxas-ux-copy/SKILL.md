# Abraxas 화면 문구

## 목소리

- 따뜻하고 짧다. 마을 사람이 옆에서 말하듯 쓴다. 시스템 메시지처럼 쓰지 않는다.
- 화면의 안내는 존댓말, 인물 대사는 `docs/story/chapters/00-overview.md`의 말투 규칙을 따른다.
- 다음 행동을 동사로 쓴다. '확인'보다 '광장으로 가기'가 낫다.
- 한 번에 한 가지만 말한다. 대사는 2줄 이내다.

## 금지

- 축 이름, 내부 코드, 성향 수치, 호감도 숫자, 'MBTI'. 내부 ID 대신 화면 이름을 쓴다.
- 측정 선택지(`content/scoring/items.json`)의 문구 변경. 필요하면 제안만 하고 사람 승인을 받는다.
- 선택 앞뒤의 평가 표현. '좋은 선택', '정답', '아쉬워요'.
- 공유 문구의 선택 내용, '그렇게 본 순간', NPC 성향과 변화, 고백 상대, 줄거리. 다른 사람의 1회차를 오염시킨다.
- 유형의 우열 암시, 사람을 재단하는 표현, 진단처럼 들리는 표현.
- 재촉과 죄책감. '지금 안 하면', '친구가 기다려요'.
- 번역투와 AI 문체. '~을 통해', '~에 있어서', '다양한', '특별한 경험'.

## 상황별

| 상황 | 쓰는 법 |
| --- | --- |
| 오류 | 무슨 일인지, 진행이 안전한지, 다음 행동. 코드를 보여 주지 않는다 |
| 저장 대기 | 선택이 안전하다는 사실을 먼저 말한다 |
| 로딩 | 기다리는 이유나 세계의 말. 진행 수치는 필요할 때만 |
| 결과 | 판정이 아니라 오늘 본 모습으로 쓴다. 고지는 그대로 둔다 |
| 공유 글자 | 플레이어가 친구에게 하는 말로 쓴다. 궁금해지는 한 줄과 링크, 게임 이름. 받는 사람 시점으로 읽고 '우리', '당신'이 누구로 읽히는지 본다. 고지는 결과 이미지와 게임 안에 둔다 |
| 공유 이미지 | 유형 이름, 그림, 가치 TOP 3까지(`docs/design/reflection-walk-plan.md`). 위 금지 목록을 지킨다 |

## 검사

```bash
node client/scripts/check-visible-names.mjs
node client/scripts/check-dialogue.mjs
```

- 위 검사는 i18n, ink, scoring만 읽는다. 'MBTI', `game.ts` 직접 글자, 조합되어 나가는 공유문은 직접 읽어 확인한다. 공유문은 코드에서 어떻게 조합되는지 따라가 실제 결과를 적는다.
- 키를 `content/i18n/ko`와 `en` 양쪽에 넣는다. 코드에 글자를 직접 쓰지 않는다. 옛 코드에 남은 글자를 보면 목록에 적는다. 그 파일의 소유권이 있을 때만 옮긴다.
- 영어는 직역하지 않고 같은 기능을 하게 쓴다.
- 문구를 적용했으면 740×360과 큰 글자 20px에서 잘리지 않는지 실제 화면으로 본다. 감사만 했으면 미확인으로 적는다.
- 긴 한국어 윤문은 `humanize-korean:humanize-korean`을 쓴다. 의미와 고유 표현이 바뀌지 않았는지 다시 본다.

## 결과 형식

```text
심각도(P0~P2) | 위치 | 현재 | 제안 | 이유 | 담당
```

설치돼 있으면 `design:ux-copy`도 참고한다. 충돌하면 이 스킬이 우선한다.
