# 디자인 정책

세부 기준과 프롬프트 예시는 `docs/art/style-guide.md`. 이 파일은 지켜야 할 경계만 담는다.

## 고정 사항

- 화면은 가로 우선, 16:9를 구성 기준으로 삼고 844×390, 740×360처럼 긴 가로 화면부터 1280×720까지 지원한다. 실제 뷰포트에 맞춰 렌더러·카메라·UI를 리사이즈하며 CSS로 화면을 회전하지 않는다. 세로 모바일에는 회전 안내 오버레이를 표시하고 위치·대화·선택 상태를 유지하며 이동 입력을 해제한다. 검증 해상도는 844×390, 740×360, 960×540, 1280×720이다.
- 쿼터뷰(3/4 탑다운) 시점. Three.js 3D 월드를 정사영 카메라로 표시한다.
- 캐릭터는 SD 2~2.5등신. 공략 캐릭터 4명은 성별 중립 디자인. 주인공은 외형 요소를 최소화한 단일 디자인(커스터마이징 없음).
- 파스텔 바탕 + 자연색 포인트. 그림자는 배경에 구워 넣는다(실시간 광원 없음).
- 감정 표현은 머리 위 이모티콘 버블. 단, 측정 문항 반응에는 하트·물음표 버블을 쓰지 않는다(`game-design-policy.md`).

## UI 규칙

- 이동 패드는 왼쪽 아래, 상호작용 버튼은 오른쪽 아래에 둔다. 대사창은 화면 하단, 선택지는 2~3개의 큰 버튼.
- 터치 영역은 최소 48×48 (기준 해상도 픽셀).
- 본문 글자는 기준 해상도에서 28px 이상. 글자 크기 조절 옵션 제공. 대사 자동 넘김은 끌 수 있어야 한다.
- 본문 텍스트 대비 4.5:1 이상.
- 선택지 버튼은 모두 같은 모양·색·크기. 순서나 색으로 '정답'처럼 보이게 하지 않는다.
- 성향치·축 이름·호감도 숫자는 플레이 중 노출 금지. 호감도는 에피소드 끝 하트 5칸만.
- 진행도는 상단 '기억 조각 n/12'.

## 에셋 규칙

- 파일명: `kebab-case`, 접두어로 종류 표시 (`bg-`, `chr-`, `ui-`, `fx-`, `card-`). 예: `chr-lumi-idle.png`.
- 캐릭터·UI 에셋은 투명 배경 PNG. 배경은 WebP.
- 초기 로딩 묶음(첫 화면~프롤로그)은 10MB 이하. 나머지는 에피소드별 지연 로딩.
- 텍스처는 아틀라스로 묶는다. 한 장 최대 2048×2048.
- 생성형 AI로 만든 에셋은 `assets/_generated/`에 두고, 사람이 고른 것만 `client/public/assets/`로 옮긴다. 프롬프트는 같은 이름의 `.prompt.md`로 남긴다.
- 실존 캐릭터·브랜드·작품을 닮은 에셋은 쓰지 않는다.
